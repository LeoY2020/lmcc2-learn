    第 14 章 输出格式约束¶

    本章目标

    掌握"零容忍格式"的写法：目标答案整行照抄、空格与大小写点名、禁止解释与代码块，并知道怎么在本地验证 Prompt 长度。

    14.1　格式三个杀手¶

    失分点 表现 Prompt 里怎么写
    空格 冒号后 0 个或 2 个空格 "冒号后恰好一个半角空格"（写出"恰好"，别只说"一个空格"）
    大小写 [route]: account "类别名必须全部大写，只能从下面三行中选一行"
    多余内容 前面加"好的，根据规则……"，或用代码块包起来 "只输出这一行；不要任何解释、标点、引号或代码块"

    必背：格式模板写法

    在 Prompt 里把允许的输出整行原文列出来，并说明"必须原样复制"： [Route]: ACCOUNT　/　[Route]: BILLING　/　[Route]: OTHER "只能输出上面三行中的一行，冒号后恰好一个半角空格，不要输出其他任何内容。"

    14.2　为什么"示例"比"描述"管用¶

    小模型的模仿能力远强于理解能力。给它两三条"输入 → 输出"的对照，比写一段"请严格遵循格式"的形容词有效得多：

    示例：
输入：账号恢复后需要办理退款 → 输出：[Route]: ACCOUNT
输入：校园卡余额异常，请帮忙核查 → 输出：[Route]: BILLING
输入：自习室的座位如何预约？ → 输出：[Route]: OTHER

    坑

    示例有两个不能碰的红线：① 不要照抄公开测试点的完整输入（隐藏点换一批输入，背答案毫无意义，甚至可能被判定为不当优化）；② 不要写太长——300 Token 很紧，示例是"最贵"的内容。挑最有代表性的、或者自己构造一两个中性例子。

    14.3　在本地量 Token 长度¶

    第一题的长度限制按平台固定的 Qwen 分词器计数。本地环境装了 Transformers，可以自己量：

    from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")   # 用本地已有的 Qwen 分词器
prompt = """你的 System Prompt 全文……"""

ids = tok(prompt)["input_ids"]
print("token 数：", len(ids))
print("字符数：", len(prompt))     # 字符数只是参考，平台看的是 token 数

    技巧

    中文经验值：1 个汉字通常约 1 个 token（视分词器而定，标点、数字、英文单词可能各占一个或多个）。所以 300 Token 大致对应"两百多不到三百个汉字 + 少量英文标点"。写 Prompt 时把上限记成"约 280 汉字"最保险，并用上面的脚本实测。

    14.4　超长时的删减顺序¶

    • 删客套与形容："你是一个非常细心、认真、专业的助手……"这类句子价值最低；

    • 合并同类规则：把"不要解释""不要加标点""不要代码块"合并成一句；

    • 示例减到最少但保留覆盖面：一个"标准情况" + 一个"反直觉情况"通常够；

    • 最后才删关键约束——格式和优先级永远不能删。

    本章要记住的 4 件事

    • 格式三杀手：空格数量、大小写、多余内容；Prompt 里要逐条点名。
    • 把允许的输出整行抄进 Prompt，并要求"原样复制"。
    • 示例有效但"贵"；不要抄公开测试点，不要堆砌。
    • 用本地 Qwen 分词器实测 token 数；超长时先删客套话与形容词。
