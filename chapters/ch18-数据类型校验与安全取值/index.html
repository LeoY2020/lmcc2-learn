    第 18 章 数据类型校验与安全取值¶

    本章目标

    掌握处理"不可信输入"的标准套路：isinstance、白名单校验、安全取值、跳过与报错的分工，写出遇到 null 也不会崩的函数。

    18.1　为什么函数测试里会有 null¶

    题面明确提示：公开函数测试可以包含 null 等非对象值，应当跳过。这是数据处理函数的基本素养——输入永远可能有脏数据，函数要么跳过它，要么在真正无法继续时抛出异常，绝不能"意外崩溃"。

    输入形态 正确反应 错误反应
    None / null 跳过（continue） 直接 r["sequence"] → TypeError
    数字、字符串、列表 跳过（不是字典） 当成字典用 → 报错
    字典但缺字段 跳过 KeyError
    字段存在但类型不对（数字、null） 跳过 AttributeError（对整数调 .strip()）
    records 本身不是列表 抛 ValueError 静默返回空列表（规格不允许）

    坑

    "跳过"和"报错"的界线是规格划的：单条记录有问题 → 跳过；整个输入的结构不对（不是列表）→ 抛 ValueError。把两者搞反，函数测试点就会直接失分。

    18.2　三个必备工具¶

    # 1) 类型判断：isinstance(x, 类型)
isinstance(records, list)          # 是不是列表
isinstance(r, dict)                # 是不是字典
isinstance(r["sequence"], str)     # 字段是不是字符串（注意 bool 是 int 的子类，
                                   #   但本题只关心 str/int 之类，用 isinstance 足够）

# 2) 字段是否存在：用 in 判断，而不是 try/except
if "sequence" in r and "valid" in r:
    ...

# 3) 安全取值：dict.get(键, 默认值) 不会抛 KeyError
v = r.get("valid", "")

    技巧

    在本题里推荐"显式检查"而不是 get 默认值：规格要求"缺少字段 → 跳过"，而 get 拿到默认值后会继续处理，容易被误当成有效记录。用 in + isinstance 把两类不合格都挡在门外，语义最清晰。

    18.4　练习¶

    records = [
    None,                                  # (a)
    "sequence",                            # (b)
    {"sequence": "()"},                    # (c)
    {"sequence": 12, "valid": "YES"},      # (d)
    {"sequence": "()", "valid": None},     # (e)
    {"sequence": "()", "valid": "YES", "extra": 1},   # (f)
]

    问：哪些会被跳过？哪一个不该因为"多了个 extra 字段"而被跳过？（答案：a～e 全部跳过；(f) 应当保留——规格说"只读取这两个规定字段，其他字段忽略"，多出来的字段不影响。）

    本章要记住的 4 件事

    • 不可信输入的标准反应：None／非字典／缺字段／类型不符 → 跳过；整体结构不对 → 抛 ValueError。
    • 三件工具：isinstance、in、dict.get；本题优先用前两个做显式检查。
    • 骨架顺序：整体类型 → 单条类型 → 字段存在 → 字段类型。
    • 多出来的字段要忽略，不能因为"多余字段"而丢弃一条本来合法的记录。
