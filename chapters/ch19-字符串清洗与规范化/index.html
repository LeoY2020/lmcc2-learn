    第 19 章 字符串清洗与规范化¶

    本章目标

    把"删除全部空白""只允许某类字符""长度必须 2～12""去首尾空白并转大写"这四类字符串操作写对、写全、写稳。

    19.1　空白：strip、replace、正则，选对工具¶

    需求措辞 正确写法 为什么不能用别的
    "去掉两端空白" s.strip() 用 re.sub 也没错，但没必要
    "删除全部空白字符" re.sub(r"\s+", "", s) strip() 只去两端，中间的空白会留下
    "删除空格（只要半角空格）" s.replace(" ", "") 若还包含制表符、全角空格，就会漏掉

    \s 在 Python 正则里匹配空白字符：半角空格、制表符 \t、换行 \n、回车 \r，也包含全角空格（在 Unicode 模式下）。"删除全部空白"用 re.sub(r"\s+", "", s) 最稳。

    考试怎么考

    第二题的公开测试点 P01 里，"( )(())" 必须变成 "()(())"——中间那个空格要去掉；P02 里 " ( ( ) ) " 必须变成 "(())"——被空格拆散也要能拼回来。这正说明"去全部空白"不能用 strip。

    19.2　字符集与长度：白名单比黑名单安全¶

    import re

# 白名单：整串只能由 ( 和 ) 组成
if re.fullmatch(r"[()]+", seq) is None:
    continue

# 等价写法（不依赖 re 也行，但要注意性能）
if any(ch not in "()" for ch in seq):
    continue

# 长度约束：必须在 2 到 12 之间
if not (2 <= len(seq) <= 12):
    continue
    写法 含义 易错点
    fullmatch 整串完全匹配模式 用 match 只匹配开头，"(a)" 会误通过
    [()] 字符类：括号里的任一个字符 忘记 + 会要求恰好一个字符
    白名单（允许什么） 只接受规定字符 ——（推荐）
    黑名单（禁止什么） 只排除某些字符 想不到 "(a)"、"(1)"、全角括号 （） 就漏了

    坑

    题面说的是"半角圆括号"，所以全角括号 （ ） 是不允许的。白名单写法 [()] 天然把全角括号排除在外；如果你用 s.replace("（", "(") 之类的"贴心的归一化"，反而违背规格。

    19.3　大小写与白名单校验¶

    v = raw.strip().upper()          # 先去掉首尾空白，再统一大写
if v not in ("YES", "NO"):       # 白名单：只接受这两个
    continue

    • 顺序不能反：先 strip() 再 upper()；如果先判断再清洗，" yes " 就会被误杀。

    • 用白名单而不是黑名单：写 v != "MAYBE" 只能挡住一个错值，v not in ("YES","NO") 才能挡住全部。

    • 转义与编码：JSONL 里的中文、括号都是普通字符，只要文件按 UTF-8 读写即可，不需要额外处理。

def normalize_sequence(raw):
    if not isinstance(raw, str):
        return None
    seq = re.sub(r"\s+", "", raw)
    if not (2 <= len(seq) <= 12):
        return None
    if re.fullmatch(r"[()]+", seq) is None:
        return None
    return seq

    技巧

    把"归一化"抽成独立的小函数有三个好处：主函数变得像自然语言（读起来就是规格的顺序）、单个小函数可以用 assert 精确测试、出错时一眼能看出是哪一步的问题。这是把 20 分稳稳拿到手的关键工程习惯。

    本章要记住的 4 件事

    • "去两端空白"用 strip()；"删除全部空白"用 re.sub(r"\s+", "", s)。
    • 字符集校验优先用白名单（re.fullmatch(r"[()]+", s)），并用 fullmatch 而不是 match。
    • 标签规范化顺序：先 strip() 再 upper()，再用 in 做白名单判断。
    • 把每类清洗抽成小函数，主函数只负责按规格顺序调用它们。

    第二题叫「括号序列判定」。题面本身简单得让人意外：给一串由半角圆括号组成的字符串，判断它是不是"合法"的括号序列。这件事你在 CSP-J 里大概十分钟就能写对。但这一题真正要你交的，不是一段判断程序，而是三份"让别人的模型学会判断"的材料：一份你亲手构造并逐条标注的训练数据、一个只负责清洗格式的 Python 函数、一份训练参数。

    换句话说，题目把"算法"这一层替你拿掉了，只留下"教模型"这一层。你从 CSP-J 带来的能力——穷举边界、构造反例、确认规格、自己写对拍——在这里依然是主角，只是舞台从"写循环"换成了"造数据、写清洗函数、调参数"。这一部分会用五章把这件事拆到不能再细：先看懂题面要什么，再学会造一份好数据，然后逐条吃透清洗规则并写出可以原样提交的函数，最后把参数填对、把模型自测一遍。

    第五部分要你记住的三句话

    第一，模型不会真的"推理括号"，它只是在模仿你给的例子里反复出现的模式；第二，process_data 只洗格式、不判合法性，合法性由你在造数据时自己负责；第三，公开四点只值 40 分，另外 40 分是隐藏点，所以数据要"覆盖规律"，而不是"覆盖公开点"。
