    第 20 章 数据清洗函数的实现与测试¶

    本章目标

    读完这一章，你能：一字不改地用上这份参考实现；说清每一段在防什么；把两个公开函数点 P01、P02 从输入一步步推到期望输出；并写出自己的自测脚本。

    20.1　完整参考实现¶

    下面这份代码可以直接作为 submission.py 提交。它满足第 36 章的全部六条规则。先通读一遍，不用急着抄，后面会逐段讲。

    import re
from collections import OrderedDict

def process_data(records):
    """按官方规则清洗原始记录，返回按原始顺序排列的标准记录列表。"""
    # 常量写在函数内部（规则 6）
    if not isinstance(records, list):
        raise ValueError("records 必须是列表")

    pattern = re.compile(r"^[()]{2,12}$")
    labels = ("YES", "NO")
    kept = OrderedDict()      # 记住插入顺序，实现"稳定"去重

    for record in records:
        # 规则 1：不是字典，跳过
        if not isinstance(record, dict):
            continue

        sequence = record.get("sequence")
        valid = record.get("valid")
        # 规则 1：缺字段或字段不是字符串，跳过
        if not isinstance(sequence, str) or not isinstance(valid, str):
            continue

        # 规则 2：删除全部空白，再检查长度与字符
        cleaned = re.sub(r"\s+", "", sequence)
        if pattern.match(cleaned) is None:
            continue

        # 规则 3：标签去首尾空白并转大写，只接受 YES / NO
        label = valid.strip().upper()
        if label not in labels:
            continue

        input_text = "序列：" + cleaned
        output_text = "[Valid]: " + label

        # 规则 4：按 input 稳定去重；冲突则抛 ValueError
        old = kept.get(input_text)
        if old is None:
            kept[input_text] = {"input": input_text, "output": output_text}
        elif old["output"] != output_text:
            raise ValueError("同一 input 出现不同 output：" + input_text)

    # 规则 5：返回列表，不打印、不扩增
    return list(kept.values())

    20.2　逐段讲解¶

    第 1 段：导入与函数说明¶

    import re
from collections import OrderedDict

def process_data(records):
    """按官方规则清洗原始记录，返回按原始顺序排列的标准记录列表。"""

    re 是正则表达式模块，用来"按模式找/替换文本"，这里干两件事：删空白、检查格式。OrderedDict 是"记住添加顺序的字典"，天然适合稳定去重。两个都是 collections 和标准库范围内的东西，符合规则 6。三引号里的那一行是文档字符串，说明函数用途，允许保留。

    第 2 段：开头就是类型检查¶

        if not isinstance(records, list):
        raise ValueError("records 必须是列表")

    raise 是"主动报错"的语句，ValueError 是"参数值不合适"这类错误的名字，规则 1 要求的就是它。顺序很重要：这一句必须写在循环之前，否则后面 for record in records 遇到一个字符串会去逐字符迭代，行为完全跑偏。把最严重的错误挡在门口，是写函数的通用习惯。

    第 3 段：三个常量与一个有序字典¶

        pattern = re.compile(r"^[()]{2,12}$")
    labels = ("YES", "NO")
    kept = OrderedDict()

    re.compile 把正则"预编译"成一个可复用的对象，比每次重新解析快一点，也让下面的判断更干净。^ 表示开头，$ 表示结尾，中间 [()]{2,12} 表示"2 到 12 个 ( 或 )"，所以整串必须完全由这些字符组成、且长度合规。labels 是允许的标签元组。kept 是去重用的有序字典，键是 input，值是那条标准记录。

    注意 r"..." 这个写法：字符串前面的 r 表示"原样字符串"，里面的反斜杠不被当转义符，写正则时不容易出错。

    第 4 段：循环开头做两道"跳过"检查¶

        for record in records:
        if not isinstance(record, dict):
            continue

        sequence = record.get("sequence")
        valid = record.get("valid")
        if not isinstance(sequence, str) or not isinstance(valid, str):
            continue

    continue 的意思是"放弃本轮，直接进入下一轮"。第一道检查挡掉 null 这种非字典项（P02 第一项就是它）。第二道先用 dict.get() 取字段——这个写法在字段不存在时返回 None，而不是报错——然后要求两个都必须是字符串。isinstance(x, str) 就是"x 是不是字符串"的判断。缺字段、字段是数字、字段是 None，全部在这里被跳过。

    技巧

    用 or 把两个类型检查写在一行，短路求值会让它足够快，也读得清楚。不要写成 if "sequence" not in record 再取值再用——那是两步，两步之间还要处理类型，反而更容易漏。

    第 5 段：删空白与格式检查¶

            cleaned = re.sub(r"\s+", "", sequence)
        if pattern.match(cleaned) is None:
            continue

    re.sub(模式, 替换成什么, 原字符串) 做替换。\s+ 表示"一个或多个空白字符"，替换成空串就等于把空白全部删掉。删完用预编译的 pattern.match() 检查：匹配成功返回一个对象，失败返回 None。所以 is None 就是"格式不合格，跳过整条记录"。空串、长度 1、长度超过 12、含 a 或全角括号的串，全都在这里被淘汰。

    坑

    不要用 sequence.strip() 代替 re.sub。strip() 只去两端，中间的空白会留下；那么 ( )(()) 就会变成长度 8 的 ( )(())，正则匹配失败被误删，P01 直接错一个点。

    第 6 段：标签归一化与拼接¶

            label = valid.strip().upper()
        if label not in labels:
            continue

        input_text = "序列：" + cleaned
        output_text = "[Valid]: " + label

    strip() 去首尾空白，upper() 转大写，" yes " 于是变成 "YES"。label not in labels 挡掉 "MAYBE" 这类非法标签。两行拼接是整道题的"格式核心"：序列：里的冒号是全角，[Valid]:里的冒号是半角且后面带一个空格。两处都写错一个字符，整个函数点就废了，所以务必逐字符核对。

    第 7 段：稳定去重与冲突处理¶

            old = kept.get(input_text)
        if old is None:
            kept[input_text] = {"input": input_text, "output": output_text}
        elif old["output"] != output_text:
            raise ValueError("同一 input 出现不同 output：" + input_text)

    这是全函数最巧的一段。kept.get(input_text) 取之前存过的记录：

    • 拿不到（None）→ 说明这是这个 input 第一次出现，存进去。

    • 拿得到，而且 output 相同 → 完全重复，什么都不做（相当于跳过），保留首次出现的那条。

    • 拿得到，但 output 不同 → 标签自相矛盾，raise ValueError。

    为什么用字典而不是列表？因为字典的键查找是"一次就能找到"，不用从头扫到尾；同时 OrderedDict 会记住插入顺序，最后 list(kept.values()) 拿到的就是稳定的顺序。如果用 set 去重，顺序就没了。

    第 8 段：返回¶

        return list(kept.values())

    把字典里的值转成列表返回。列表里的每一项都是新造的字典，只有 input 和 output 两个键——这正是训练数据要的格式。

    第 9 段：把整条流水线再走一遍¶

    把上面八段串起来，函数对每条记录做的事情固定是这七步：

    • 这一项是不是字典？不是就跳过。

    • 能不能取到两个字符串字段？不能就跳过。

    • 删掉 sequence 里的全部空白。

    • 删完的串是不是"2 至 12 个半角括号"？不是就跳过。

    • valid 去首尾空白并转大写，是不是 YES 或 NO？不是就跳过。

    • 拼出 input 与 output，按 input 查表：没有就存入；有且 output 相同就跳过；有但 output 不同就抛 ValueError。

    • 全部走完后，把表里的值按插入顺序变成列表返回。

    记住这七步，你就能对着任何一条数据说出"它会走到哪一步被拦住"。这在调试时特别有用：一条数据消失得不明不白，只要按顺序问一遍，马上就知道是哪一步把它拿掉了。

    20.3　完整推演公开点 P01¶

    P01 的输入与期望（题面原文）：

    records：
[
 {"sequence":"( )(())","valid":" yes "},
 {"sequence":")(","valid":"no"}
]
期望返回：
[
 {"input":"序列：()(())","output":"[Valid]: YES"},
 {"input":"序列：)(","output":"[Valid]: NO"}
]

    状态推演如下。所谓"状态推演"，就是把函数当成一台机器，输入一条、看一次状态变化，最后核对输出。

    步 取到的记录 函数内部发生了什么
    1 {"sequence":"( )(())","valid":" yes "} 是字典 → 两个字段都是字符串 → 删空白得到 cleaned = "()(())"（长度 6，只含括号，格式合格）→ 标签去空白转大写得到 "YES"，在允许清单里 → 拼出 input = "序列：()(())"、output = "[Valid]: YES" → kept 里没有这个键，存入
    2 {"sequence":")(","valid":"no"} 是字典 → 两个字段都是字符串 → 无空白可删，cleaned = ")("（长度 2，格式合格，注意不判断合法性）→ 标签转大写得 "NO" → 拼出 input = "序列：)("、output = "[Valid]: NO" → 新键，存入
    3 没有更多记录 返回 list(kept.values())，正好是期望的两条

    核对：返回两条，顺序与输入一致，键名是 input 和 output，值是期望的字符串。P01 通过。

    考试怎么考

    P01 表面上在考"删空白"和"标签大小写"，实际还藏了一个考点：第 2 条 )( 会被保留。如果谁把"合法性判断"偷偷写进函数，这条就会被当成不合法而删掉，期望的两条变成一条，P01 直接错。这就是规则 5 的现场版。

    20.4　完整推演公开点 P02¶

    P02 的输入与期望：

    records：
[
 null,
 {"sequence":" ","valid":"NO"},
 {"sequence":" ( ( ) ) ","valid":"yes"},
 {"sequence":"(())","valid":"YES"},
 {"sequence":"(a)","valid":"NO"},
 {"sequence":"()","valid":"MAYBE"}
]
期望返回：
[
 {"input":"序列：(())","output":"[Valid]: YES"}
]

    P02 是六个"陷阱"排成一列，逐个过一遍你就明白评分者想考什么了。

    步 记录 判断过程 结果
    1 null（Python 里是 None） isinstance(None, dict) 为假 跳过
    2 {"sequence":" ","valid":"NO"} 是字典、字段都是字符串；删空白后 cleaned = ""，长度 0，正则不匹配（要求 2～12） 跳过
    3 {"sequence":" ( ( ) ) ","valid":"yes"} 删空白后 cleaned = "(())"，长度 4 合格；标签 "yes" → "YES" 合格；拼出 "序列：(())" 与 "[Valid]: YES" 保留
    4 {"sequence":"(())","valid":"YES"} 格式化后 input 与第 3 步完全相同，且 output 也相同 作为重复跳过
    5 {"sequence":"(a)","valid":"NO"} 删空白后仍是 "(a)"，含字母 a，正则不匹配 跳过
    6 {"sequence":"()","valid":"MAYBE"} 格式合格，但标签转大写后是 "MAYBE"，不在允许清单里 跳过

    最终 kept 里只有第 3 步那一条，返回长度为 1 的列表，与期望完全一致。

    坑

    P02 的两个高频失分点：一是 null 没判断类型，函数直接崩溃；二是没有按规范化后的 input 去重，第 3、4 步各留一条，返回两条。还有一个小陷阱容易被忽略：第 2 步的 " " 必须被删成空串才判不合格；如果你写成"跳过显然不长于 2 的输入"却不删空白，" ( ( ) ) " 的原始长度 9 就蒙混过关、" " 也可能被不同方式处理，最终结果都会偏。

    技巧

    看这两个公开点的设计，就能反推评分者的口味：他们专门测"边界与脏数据"，而不是测"会不会写循环"。你自己造数据时也该用同样刁的胃口去挑反例。

    20.5　自测脚本：把两个公开点写成断言¶

    把公开点抄成断言，是最省事、最可靠的回归测试。assert 的意思是"我断言这个条件为真，否则就报错"。

    # test_process_data.py —— 只在本机跑，不要提交
from submission import process_data

P01_IN = [
    {"sequence": "( )(())", "valid": " yes "},
    {"sequence": ")(", "valid": "no"},
]
P01_OUT = [
    {"input": "序列：()(())", "output": "[Valid]: YES"},
    {"input": "序列：)(", "output": "[Valid]: NO"},
]
assert process_data(P01_IN) == P01_OUT, "P01 不通过"

P02_IN = [
    None,
    {"sequence": " ", "valid": "NO"},
    {"sequence": " ( ( ) ) ", "valid": "yes"},
    {"sequence": "(())", "valid": "YES"},
    {"sequence": "(a)", "valid": "NO"},
    {"sequence": "()", "valid": "MAYBE"},
]
P02_OUT = [
    {"input": "序列：(())", "output": "[Valid]: YES"},
]
assert process_data(P02_IN) == P02_OUT, "P02 不通过"

# 额外自测：不是列表必须抛 ValueError
try:
    process_data("这不是列表")
except ValueError:
    pass
else:
    raise AssertionError("records 不是列表时应当抛 ValueError")

# 额外自测：同一个 input 出现不同 output 必须抛 ValueError
CONFLICT = [
    {"sequence": "(())", "valid": "YES"},
    {"sequence": " ( ( ) ) ", "valid": "NO"},
]
try:
    process_data(CONFLICT)
except ValueError:
    pass
else:
    raise AssertionError("同一 input 冲突时应当抛 ValueError")

# 额外自测：空列表返回空列表，长度边界 2 和 12 都能保留
assert process_data([]) == []
assert len(process_data([{"sequence": "()", "valid": "NO"}])) == 1
assert len(process_data([{"sequence": "()" * 6, "valid": "YES"}])) == 1
assert process_data([{"sequence": "()" * 7, "valid": "YES"}]) == []   # 长度 14，应被清洗掉

print("全部自测通过")

    最后三行断言测的是长度边界："()" * 6 是长度 12（上边界，应保留），"()" * 7 是长度 14（超限，应被清洗掉）。这类边界自己加几条，能提前发现"范围写成了 2～13"之类的低级错误。

    考试怎么考

    平台展示的两个函数点就是 P01 和 P02，测试时完整展示输入、期望返回值、实际返回值和对错。也就是说，函数环节你不需要猜——把这两段断言跑通，20 分就到手了。剩下要防的是"本地通过、平台不通过"，常见原因就是环境差异（比如用了没被允许的库）或者细节没对齐（比如返回了字典而不是列表）。

    20.6　常见失分点表¶

    失分点 错误写法 正确做法
    函数里判断合法性 数括号、用栈判合法，把 NO 的记录删掉或改标签 只做字符和长度检查；)()(、(((( 都要原样保留
    没做类型检查 直接 record["sequence"]，遇到 null 崩溃 先 isinstance(record, dict)，再 get，再 isinstance(..., str)
    只删两端空白 sequence.strip() re.sub(r"\s+", "", sequence)，删全部空白
    长度范围写错 写成 1 <= n <= 12 或 2 < n <= 12 闭区间 2～12；用 ^[()]{2,12}$ 同时管字符
    标签没归一化 直接比较 "yes"，或忘了 upper() valid.strip().upper()，再查是否在 ("YES","NO") 里
    去重方式不稳定 用 set 或先排序 用 OrderedDict 或保序字典，保留首次出现
    按原始串去重 用 sequence 当键 用规范化后的 input 当键
    冲突不报错 同 input 不同 output 时随便留一个 raise ValueError

    • 参考实现只有三十行左右：类型检查 → 取字段 → 删空白 → 校验格式 → 归一化标签 → 拼接 → 稳定去重 → 返回列表。
    • 两个公开点 P01、P02 的期望值要能背下来，最好直接写成断言跑通。

    • P02 的关键是"null 跳过 + 空串跳过 + 按规范化 input 去重 + 非法标签跳过"。
    • 额外自测要覆盖：不是列表抛错、冲突抛错、空列表、长度 2 与 12 的边界、长度 14 被清洗。
