    第 22 章 训练数据构造与标签质量¶

    本章目标

    读完这一章，你能：说清 LoRA 到底在学什么、为什么 100 条就够用；画出一张长度 × 结构的覆盖矩阵；按四类不合法情况补齐数据；保证每条标签都可靠；并且知道哪些输入绝对不能放进训练集。

    这一章是第二题最重要的一章。参数填错，最多损失几分；数据造偏，40 分隐藏点会成片地丢。先把一个关键问题讲明白：模型到底是怎么"学会"的？

    22.1　为什么 100 条就够：LoRA 在学什么¶

    先认识三个词¶

    模型（model）：这里用的是 Qwen3-0.6B，可以理解成一台"读了很多文本、学会了接话"的机器。它内部有大约六亿个数字（叫参数），这些数字决定了它对任何输入的回应。0.6B 里的 B 是"十亿"，所以它是个很小的模型——小到可以在普通显卡上跑，也小到"很好带"。

    微调（fine-tuning）：直接改这台机器的全部参数，让它适应一个新任务。问题是很贵：要很多显存、很多时间。

    LoRA（低秩适配，Low-Rank Adaptation）：一种省钱的微调办法。它不动原来的六亿个参数，而是在模型的一些层旁边"挂"上几个很小的矩阵（你可以想象成给机器贴的便利贴），训练时只改这些便利贴。训练完，把便利贴的内容单独保存成一个很小的文件，加载时再贴回去。这样 8GiB 显存就够用了，保存和重载也很快。

    必背

    LoRA 不是"重新训练一个模型"，而是"给现成模型加一层小的、可训练的补丁"。参数 loraRank（秩）就是决定这张便利贴有多大的旋钮：4 最小、16 最大。

    那么这台机器靠什么学会"判断括号序列合法"？它靠的是模仿。你给它看成百上千次"这个输入对应这个答案"，它就去调整便利贴上的数字，让"看到这种输入就吐出这种答案"的概率变高。它没有"理解"括号配对这件事，它只是把输入的形状和你给的标签之间的统计关联记下来。

    为什么 100 条够¶

    因为这道题要学的规律非常"薄"。整道题的规律只有两条（前缀条件、结束条件），输出只有两个固定字符串。机器不需要学会写作文、算数学，只需要学会"识别括号串的形状 → 输出两种固定串之一"。这种任务叫模式识别，样本效率极高。100 条数据，每条平均十几个字符，乘以系统提示词和对话模板，总训练量已经足够让模型把输出格式稳定下来。

    但"100 条够"有个前提：这 100 条必须把规律的关键维度都覆盖到。如果 100 条里 90 条是 ()()() 这种连续结构，剩下 10 条是明显乱写的，模型学到的就是"看起来规整 = YES"，在隐藏点上照样会错。反过来，100 条安排得当，比盲目堆 1000 条更有效——何况题面本来就不许超过 100 条。

    每条数据为什么有 512 Token 的上限¶

    平台给每条训练数据留了 512 Token 的额度，里面要装下"固定系统提示词 + 对话格式标记 + 你的输入 + 正确答案"。固定系统提示词本身就有几十个 Token，对话格式的标记也要占一些，剩下的额度对你的括号串来说绰绰有余。这条限制真正防的是"把一整篇文章塞进 sequence"这类失控行为。反过来想：额度这么宽松，说明成绩根本不取决于你把数据写多长，而取决于你写得多准。与其在一条数据里塞更多字，不如多造几条覆盖不同结构的短数据。

    再强调一次 Token 和汉字的关系：对中文来说，大约一个字对应一个 Token，标点和英文单词也各占若干。所以你不需要精确计算，只要保证 valid 里除了 YES/NO 什么都不写、sequence 里只有 2 至 12 个括号，就永远不会踩到这条线。

    顺便认识"过拟合"¶

    过拟合（overfitting）：模型把你的训练数据背下来了，而不是学到规律。表现的典型症状是：训练集上几乎全对，一换没见过的输入就错。在本题里，过拟合最常见的形态就是——你的数据里所有"数量相等"的串都是 YES，模型于是学会"数一数，相等就 YES"，在 )()( 这类平衡但顺序错的串上全军覆没。

    坑

    把训练轮数（epochs）从 8 加到 12，并不能治好"规律学错了"这个病，只会让模型把错误规律背得更牢。增加训练轮数不保证成绩提高，题面原话。数据覆盖不对时，调参数是白费力气；先回去检查数据。

    22.2　覆盖矩阵：长度 2/4/6/8/10/12、连续 vs 嵌套、合法 vs 不合法¶

    构造数据最怕"凭感觉随机生成"。用 CSP-J 的思路：先列一张测试矩阵，横轴是长度，纵轴是结构类型，然后逐格填例子。填满之后你就会得到一个几乎没有盲区的数据集。

    长度为什么只放偶数？因为奇数的合法序列根本不存在，但奇数长度本身是一种"不合法原因"，所以奇数长度要放在不合法那一侧当反例，而不是当合法的目标。下面的矩阵把长度 2/4/6/8/10/12 作为主骨架（都是合法的目标长度），另外单独配奇数长度的反例。

    为什么长度这个维度必须单独列出来？因为模型的"经验"高度依赖它见过什么。如果训练数据全是长度 2 到 4 的小串，模型很可能把"短串"和"合法"关联起来；一旦遇到长度 10 的隐藏点，它的直觉就可能出错。反过来，如果 2、4、6、8、10、12 每个长度都见过合法的连续型、嵌套型和混合型，模型学到的就是"不管多长，只要满足那两条规则就 YES"，这才是能迁移到新输入上的规律。

    技巧

    别手工敲这几十条，容易敲错。写一个小脚本把某个长度下的所有括号串枚举出来，再用一个独立的检查函数打标签，最后按"连续、嵌套、四类不合法"分组各取样若干条。脚本生成的串不会打错字符，标签也不会手滑。具体脚本见 20.6 节。

    每种结构至少要几条¶

    "覆盖"不等于"每格一条就完事"。模型要从多个例子里归纳出规律，同一个类型给三五条不同长相，它才敢确认这是规律而不是巧合。一个可执行的分配建议（总数控制在 100 条以内）：

    类别 建议条数 理由
    连续型合法（各种长度） 15～20 提供最基础的正例，覆盖长度维度
    嵌套型合法 15～20 嵌套和连续形状差别大，要都见过
    混合结构合法 20～25 真实隐藏点多半长这样，让模型不靠"形状规整"蒙
    未闭合 10～15 训练结束条件
    额外右括号 10～15 训练过程条件（提前变负）
    数量相等但顺序错 15～20 最重要的一类，专门打掉"数量相等就是合法"的捷径
    奇数长度 5～10 反例，同时让模型见过奇长度也应是 NO

    22.3　必须覆盖的不合法类型（含会给清洗掉的边界）¶

    把 18.2 的不合法部分再钉一遍。下面这张表是"最低清单"：每一项都至少要有几条，缺一项都可能对应一个隐藏点丢分。

    • 未闭合：左括号开得比关得多。短到 ((，长到 ((((((；也要有"看起来就差一步"的 (() 和 (()(()。这类数据教会模型看结束条件。

    • 额外右括号：某个前缀里右括号超了。))、())、())))。这类数据教会模型看过程条件。

    • 数量相等但顺序错：)(、)()(、())(()、())()(、)((())()()。这类数据是拆掉"数数量"捷径的唯一武器。

    • 奇数长度：()(、())、((())、()()()()(。长度是奇数时结束条件不可能满足，模型一旦学会"奇长度 → NO"，就能省下不少力气。

    • 边界情况：长度正好 2 的 ()（最短合法）和 )(（最短不合法）；长度正好 12 的合法与不合法各来一条，确认模型不被长度上限影响到判断。

    坑

    有些"看起来该有"的数据，会被 process_data 直接清洗掉，根本进不了训练集：空字符串 ""、只有 1 个字符的 ( 或 )、长度超过 12 的串（比如 14 个字符）、以及含有空格外字符的 (a)。规则是"删除全部空白后长度必须为 2 至 12，且只能包含半角圆括号"，不满足就跳过整条记录。所以：不要把空串和超长串当作训练数据的主力，它们只会让你的有效数据变少；但你可以故意留一两条用来验证自己的函数确实会跳过它们（前提是总数留有余量，清洗后仍要 ≥1 条）。另外，长度恰好 1 的 ( 虽然也是"未闭合"，但它在本题里属于会被清洗掉的边界，不能作为代表未闭合的主要样本。

    22.4　标签可靠性：不要出现错标，不要只靠"左右数量相等"¶

    标签（label）就是你写在 valid 字段里的 YES 或 NO。它是正确答案，不是"你觉得"。题目把话说到最硬：输入是否合法、标签是否正确，需要在构造数据时由你确认；process_data 只负责复制你的标签，不做任何判断。也就是说，标错一条，模型就学错一条，没有任何程序会替你兜底。

    一个可靠的打标签方法¶

    用你熟悉的"记账"法，写成一个小函数：从左到右扫，遇到 ( 记 +1、遇到 ) 记 -1；任何时刻账本变成负数就判 NO；扫完账本必须是 0，否则 NO。两次条件一起判，逻辑上等价于题面两条规则。这个函数只用在你自己的造数据脚本里，绝不要写进 submission.py（那会违反规则 5）。

    为了保险，还可以用第二种方法交叉验证：数一数左括号和右括号的个数，如果总数不相等，那一定是 NO；如果总数相等，再用上面的记账法确认过程条件。两种方法对同一条数据给出不同结论时，一定是哪里写错了，必须查清楚。

    要小心的几个"看起来像对的"标签¶

    序列 正确标签 如果只看"数量相等"会怎么错
    )( NO 数量 1 比 1 相等，容易被误标 YES——这就是题面点名的反例
    )()( NO 数量 2 比 2 相等，且首尾对称，极具迷惑性
    ())(() NO 数量 3 比 3 相等，第 3 个字符处账本变负
    ((())) YES 数量相等且过程安全，真合法
    (())() YES 数量相等且过程安全，真合法

    必背

    题面原话：不要让"左右数量相等"成为训练数据中判断合法的唯一线索。具体做法就是——在数据集里安排足够多"数量相等但顺序错"的 NO，让模型没法用"数数量"这条捷径过关。

    技巧

    自检标签有一套土办法，很有效：把 100 条数据按标签分组，分别统计它们的长度分布和"数量相等"的比例。如果所有 NO 都是"数量不相等"的，而所有"数量相等"的都是 YES，那你的数据几乎肯定有坑，必须补第三类。反过来，如果 YES 和 NO 在长度上都有分布、NO 里有一批"数量相等但顺序错"，这份数据就靠谱了。

    22.5　禁止把 4 个公开模型测试点的输入放进训练集¶

    题面写得很明确：不得把四个公开模型测试的完整输入直接加入训练集，也不得仅改变空格后加入。四个公开点的输入是（第 23 章还会用到）：

    点 输入 标准答案 说明
    M01 序列：(()(()())) [Valid]: YES 合法的混合结构，长 10
    M02 序列：((())())() [Valid]: YES 合法的混合结构，长 10
    M03 序列：())(()())( [Valid]: NO 不合法，长度 10 但顺序错
    M04 序列：((()())())( [Valid]: NO 不合法，长度 11（奇数）且未闭合

    为什么不许放？两个层面的原因。第一是规则层面：这是题面的明文禁令，违反它等于自己给自己挖坑。第二是能力层面：把公开点原样放进训练集，等于考试前先背答案——它在公开四点上分数很好看，但模型学到的是"这几个特定串对应这几个特定答案"，对没见过的隐藏点毫无帮助，反而因为挤占了 100 条的额度，让真正有用的覆盖样本变少。

    坑

    "仅改变空格后加入"也被明确禁止。比如把 序列：(()(()())) 改写成 序列： (()(()())) 再放进训练集，仍然是违规，而且在训练里几乎不会带来任何差异。判断标准很简单：你的数据里，不该出现和公开点长得几乎一样的输入。要覆盖的是"长 10 的混合结构合法串"这个规律，而不是这一条具体的串——你可以用 (()())(())、((())(())) 这样的同规律样本，它们既覆盖了规律，又不是公开点本体。

    return result

    逐段解释：

    • is_valid 是唯一的标签来源。它把两条规则写在同一个循环里：过程条件靠 `depth s.count(")")] bad_extra = [s for s in bad if s.count(")") > s.count("(")] bad_balanced = [s for s in bad if s.count("(") == s.count(")")] picked.extend(bad_unclosed[:2]) picked.extend(bad_extra[:2]) picked.extend(bad_balanced[:3]) # 数量相等但顺序错，最重要

    2) 去重并按原始顺序打包成 JSONL 记录¶

    rows = [] seen = set() for s in picked: if s in seen: continue seen.add(s) rows.append({"sequence": s, "valid": "YES" if is_valid(s) else "NO"})

    3) 兜底：保证总量不超过 100；不够就补长一点的混合合法串¶

    rows = rows[:100] with open("train.jsonl", "w", encoding="utf-8") as f: for row in rows: f.write(json.dumps(row, ensure_ascii=False) + "\n")

    print("写出条数：", len(rows)) 

    关键点在挑选那一段：**合法串按长度均匀取，不合法串按"错在哪"分类取**。`bad_balanced` 这一行尤其重要，它专门捞"数量相等但顺序错"的串，也就是整个数据集里最值钱的那一批。`json.dumps(..., ensure_ascii=False)` 可以不写转义、直接把中文写成中文；`json.dumps` 负责把字典变成一行合法 JSON，我们只管在末尾补一个换行符，这就是 JSONL（每行一个 JSON 对象）。

!!! tip "技巧"
    这个脚本给的是骨架，你可以把它当模板改成"每种不合法类型各取 6 条"的版本，把额度分得更均匀。改造时守住一条：标签永远只由 is_valid 产生，绝不用手写字符串。

### 抽检：三类检查

写完 `train.jsonl` 后不要马上去训练，先抽检。`submission.py` 写好后，用下面这段代码一次性查三件事。

```python
# check_data.py —— 抽检脚本
import json
from collections import Counter
from submission import process_data

# 第一件事：文件本身的形状
with open("train.jsonl", encoding="utf-8") as f:
    lines = [ln for ln in f.read().split("\n") if ln.strip()]
records = [json.loads(ln) for ln in lines]
print("原始条数：", len(records), "（必须 1 到 100）")
print("标签分布：", Counter(r["valid"] for r in records))
print("长度分布：", Counter(len(r["sequence"].replace(" ", "")) for r in records))

# 第二件事：清洗后还剩多少，有没有被误删
cleaned = process_data(records)
print("处理后条数：", len(cleaned), "（必须 1 到 100）")
print("处理后再去重：", len({c["input"] for c in cleaned}))

# 第三件事：把标签重新独立验算一遍，找出错标
def twice_check(seq):
    if seq.count("(") != seq.count(")"):
        return "NO"
    depth = 0
    for ch in seq:
        depth = depth + (1 if ch == "(" else -1)
        if depth < 0:
            return "NO"
    return "YES"

bad = [r for r in records if twice_check(r["sequence"]) != r["valid"]]
print("可疑错标条数：", len(bad))
for r in bad[:10]:
    print("  检查：", r)

# 额外提醒：NO 里有多少是"数量相等但顺序错"
balanced_no = [r for r in records
               if r["valid"] == "NO"
               and r["sequence"].count("(") == r["sequence"].count(")")]
print("数量相等却是 NO 的条数：", len(balanced_no), "（太少就是数据有坑）")

    读这段输出要像做题一样：原始条数在 1 到 100 之间；处理后条数最好等于原始条数（说明没有记录被清洗规则误删，或者你故意放的那一两条边界被删掉后仍有余量）；可疑错标条数为 0；数量相等却是 NO 的条数不为 0，最好和"数量相等且是 YES 的条数"在同一个量级。

    考试怎么考

    这些抽检只是你自查用的，不影响得分；但它们能在训练之前就把"数据错标"这种致命问题拦下来。要知道，模型点在训练完成、保存并重载 LoRA 之后才有反馈，而训练是要花时间排队和跑 GPU 的。等你发现公开点全错再回头改数据，时间可能已经不够了。所以：数据自查 → 函数自查 → 再点训练，这个顺序不能反。

    22.7　第二题的数据要求：把官方数据原则落到 1～100 条上¶

    官方原则 第二题里的做法
    类别要平衡 合法序列与不合法序列数量尽量接近（各约 50 条）。官方指出严重不平衡时小批次里可能一个少数类样本都没有；同时提醒"准确率在不平衡数据上不可靠"——对第二题来说，模型只答"YES"也能蒙对一半。
    测试集不能进训练集 公开模型测试点的完整输入（以及只改空格的版本）官方明令禁止放入 train.jsonl；这与"训练集与测试集必须不同"是同一个道理。
    重复样本会虚高分数 官方建议拆分后删除与训练集重复的样本；本题表现为"不要靠重复同一模式凑数量"，构造时就去重。
    数据格式以任务为准 标准格式与对话格式是两套写法（{"text": ...} 与 {"messages": [...]}），本题用 sequence / valid 字段——以题面模板为准。

    22.8　覆盖矩阵：100 条数据该写什么¶

    维度 取值 建议
    长度 2、4、6、8、10、12 每种长度均匀分布
    结构 连续型 ()()、嵌套型 (())、混合型 合法样本覆盖三类
    不合法原因 未闭合、额外右括号、数量相等但顺序错、奇数长度 每类至少 8～10 条
    标签 YES / NO 两类各约一半

    坑

    只构造"数量相等/不等"两类样本，是最常见的失败方式：模型会学成"数括号数量"，遇到 )( 这种数量相等但顺序错的序列就答错。

    本章要记住的 7 件事

    • LoRA 是给现成模型挂一层小的可训练补丁，不改原参数；loraRank 决定补丁大小。
    • 100 条够用，是因为这道题规律很薄；但前提是覆盖到位，否则模型只会学到"数量相等就是合法"。
    • 覆盖矩阵的横轴是长度 2/4/6/8/10/12，纵轴是连续、嵌套、混合、四类不合法。
    • 四类不合法是未闭合、额外右括号、数量相等但顺序错、奇数长度；第三类最关键。
    • 空串、长度 1、长度超过 12、含非括号字符的串都会被 process_data 清洗掉，别让它们占额度。
    • 标签只能由独立的检查函数产生，绝不用手写；写完要抽检"数量相等却是 NO"的条数是否为 0 之外。
    • 四个公开模型点的完整输入（以及只改空格的版本）绝对不能放进训练集。
