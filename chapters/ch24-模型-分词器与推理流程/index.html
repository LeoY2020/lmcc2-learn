    第 24 章 模型、分词器与推理流程¶

    本章目标

    学完这一章，你能：① 说清楚"模型、分词器、输入张量"这三个角色各干什么；② 看懂 from_pretrained、trust_remote_code、device_map="auto"、torch_dtype=torch.float16 这四个参数为什么这么写；③ 照着抄出一段能跑起来的最小推理代码，并且知道每一行在做什么。

    从这一章开始，我们正式进入"动手"的部分。前面几章你已经知道：考试要你改的是 submission.py 里的几个函数，评测程序会把你的函数调起来，喂给它题目，再检查它输出对不对。可这些函数里到底发生了什么？为什么一段提示词（Prompt）丢进去，就能吐出答案？

    用一个比喻先垫一下：把大模型想成一位只会说"数字语"的老师。你写的中文句子他听不懂，必须先交给一个翻译官，把句子翻成一串数字（这串数字叫 token id）；老师读完这串数字，再一个数字一个数字地往外蹦，说出他的答案（也是一串数字）；最后还要请翻译官把老师的数字再翻回中文。这场"翻译—回答—翻译"的接力里，一共有三个角色：模型（model）、分词器（tokenizer）、输入张量（tensor）。这一章就把这三个角色掰开揉碎讲清楚。

    24.1　先看懂三个角色：模型、分词器、输入¶

    角色一：分词器（tokenizer）——负责"翻译"¶

    分词器的英文是 tokenizer，"token" 可以理解成"词块、字块"，"-izer" 是"做这件事的工具"。所以分词器就是把文本切块、并把每一块对应成一个整数编号的工具。它手里有两本"字典"：

    • 正向字典：文本 → 编号。比如把 "12 + 35" 切成若干块，每块查出一个整数，拼成 [16, 220, 458, ...] 这样的整数列表；

    • 反向字典：编号 → 文本。拿到一串整数，能拼回人看得懂的句子。

    这里要建立一个非常重要的直觉：模型永远只跟整数打交道。不管是你的题目、system prompt、还是模型回答的答案，在模型眼里全是整数。你在评测程序输出里看到的 input_ids，就是"输入文本被翻译成的那串整数"。

    必背

    模型看不见汉字，只看得见整数。所以任何文本要送进模型，都必须先过一遍 tokenizer(...)；模型吐出来的任何东西，也必须过一遍 tokenizer.decode(...) 才能变回中文。这两步但凡漏一步，程序要么报错，要么给你一串看不懂的数字。

    角色二：模型（model）——负责"接着往下猜"¶

    做题用的是 AutoModelForCausalLM。拆开看：Auto 是"自动帮我挑合适的类"，Model 是"模型"，ForCausalLM 是"用来做因果语言模型（Causal Language Model）"。

    什么叫"因果语言模型"？就是根据前文预测下一个 token 的模型。你给它 [12, 220, 458]，它会算一个概率分布：下一个数字最可能是几、第二可能是几……然后挑一个出来，接在后面变成 [12, 220, 458, 3921]；再拿这串更长的，接着猜下一个。就这样一个接一个地往外蹦，直到蹦出"结束符"或者到达你规定的上限。整个过程叫生成（generate）。

    所以"模型回答你的问题"这件事，真相非常朴素：它不查表、不搜索、不推理公式，它就是不停地猜下一个数字。所谓"会做数学题"，是说它被训练得在这类前文后面，能猜出正确的数字。这也解释了为什么 Prompt 写得好不好很关键——你给的前文不一样，它往下猜的方向就不一样。

    角色三：输入张量（tensor）——负责"打包搬运"¶

    张量（tensor）这个词听着吓人，其实在考试里你只需要理解成：就是一组排好队、带形状的数字。一维是列表，二维是表格，三维是"一叠表格"。PyTorch 里所有数据都是张量。

    为什么非要用张量，不能用普通 Python 列表？因为模型内部要做海量矩阵乘法，张量能把整批数字一次性、按固定形状丢给显卡或 CPU 算，速度快几十倍。所以分词完，我们要跟 tokenizer 说一句"用 PyTorch 的格式给我"——这就是 return_tensors="pt" 的作用（pt = PyTorch）。

    三个角色串起来¶

    角色 它是什么 在代码里长什么样
    分词器 文本 ↔ 整数编号的翻译官，自带字典 tokenizer = AutoTokenizer.from_pretrained(...)
    模型 根据前文预测下一个 token model = AutoModelForCausalLM.from_pretrained(...)
    输入张量 排好队、带形状的数字（PyTorch 格式） inputs = tokenizer(text, return_tensors="pt")，得到 input_ids 等

    技巧

    记不住顺序就记这句话："文本进分词器，变成张量；张量进模型，变出新张量；新张量再进分词器，变回文本。"从左到右读三遍，第 27 章那条完整链路你就已经记住一半了。

    24.2　from_pretrained 与 trust_remote_code¶

    先说一个现实问题：训练一个大模型要花很多钱、很多时间，考试当然不可能让你现场训练。所以我们要用的是已经训练好的、存在硬盘上的模型。把它从硬盘读进内存，这个动作就叫"加载预训练模型"。

    加载靠两个函数：AutoTokenizer.from_pretrained(...) 和 AutoModelForCausalLM.from_pretrained(...)。from_pretrained 直译"从预训练（的模型）来"，它的第一个参数是模型的名字或者路径。

    官方评测程序里的加载代码（原样引用）¶

    tokenizer = AutoTokenizer.from_pretrained(
    model_name,
    trust_remote_code=True,
    padding_side="left",
    truncation_side="left",
)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    trust_remote_code=True,
    device_map="auto",
    torch_dtype=torch.float16,  # 使用半精度，显存占用减半
)
if tokenizer.pad_token_id is None:
    tokenizer.pad_token = tokenizer.eos_token
model.config.pad_token_id = tokenizer.pad_token_id

    这段代码来自 T1 例题的 evaluate.py。注意一个关键事实：这段加载代码是评测程序自己写的，你不需要在 submission.py 里再写一遍。评测程序加载好模型和分词器，然后把它们当参数传给你的函数。所以你的函数签名里才有 model 和 tokenizer 这两个参数。

    那你为什么还要学它？三个理由：第一，你要读懂评测程序，才知道传进来的 tokenizer 已经被设置成什么样了；第二，你自己写小脚本调试、或者做 T2 类似的题时，要会自己加载；第三，参数怎么设直接影响你的答案对不对（比如左填充），不懂就查不出错。

    model_name 从哪来¶

    MODEL_NAME = os.environ.get("MODEL_NAME", "../Qwen/Qwen3-0.6B")

    这行的意思是：先去看操作系统的环境变量里有没有 MODEL_NAME；如果有，就用它；如果没有，就用默认的 "../Qwen/Qwen3-0.6B"。os.environ.get(名字, 默认值) 就是这个"取不到就用默认值"的写法。

    • Qwen3-0.6B 是模型的名称，其中 B = Billion = 十亿，所以 0.6B 表示这个模型大约有 6 亿个参数。它在同系列里属于"最小号"，专门用来让普通电脑也能跑得动。

    • 路径前面的 ../ 表示"上一层目录"。也就是说，评测程序默认到自己的上一层目录去找 Qwen/Qwen3-0.6B 这个文件夹。这是考试环境的目录安排，不要自己改成别的路径。

    • 用环境变量的好处：正式评测时，老师可以不改你的代码，直接把 MODEL_NAME 设成别的模型。

    考试怎么考

    评测程序里 MODEL_NAME = os.environ.get("MODEL_NAME", "../Qwen/Qwen3-0.6B") 是固定写死的（见 T1 例题 evaluate.py）。你的 submission.py 里不要再自己写一遍模型路径去加载模型——你要用的是评测程序传进来的那个 model。自己另加载一份，既浪费时间又占内存，还可能因为路径不对直接报错。

    trust_remote_code=True 是什么意思¶

    有些模型（尤其是国产模型）除了权重文件，还附带了自己的 Python 代码，用来定义这个模型特有的结构。默认情况下，Transformers 出于安全考虑，不会执行别人给的代码，于是加载时报错或者功能不全。trust_remote_code=True 就是告诉它："这个模型的代码我信任，请执行它。"

    一句话记：trust = 信任，remote code = 远端（模型作者提供的）代码，True = 允许执行。

    坑

    只对你信得过的模型目录开 trust_remote_code=True。它的本质是"允许模型文件夹里的 Python 代码在你电脑上运行"。考试环境里模型是官方给的，开这个没问题；但如果你以后在网上随便下载一个陌生模型，就要先想清楚。

    坑

    如果你的函数里报 TypeError: ... got an unexpected keyword argument 'trust_remote_code'，通常是两个原因之一：① 你把 trust_remote_code 传给了不该传的地方（比如传给了 tokenizer(...) 这个"加工文本"的调用，而不是传给它左边的 from_pretrained(...)）；② 括号没配平，参数串到了别的函数里。改参数前先数括号。

    24.3　device_map="auto" 与 torch_dtype=torch.float16¶

    这两个参数都写在 AutoModelForCausalLM.from_pretrained(...) 里，一个决定"模型放哪儿算"，一个决定"模型用什么精度算"。它们是考试环境能不能跑起来的关键。

    device_map="auto"：模型放哪儿¶

    设备（device）这个词在 PyTorch 里指"真正执行计算的地方"，主要有三种：

    设备 代码里的写法 特点
    CPU cpu 人人都有，但算得慢，适合小模型
    GPU（NVIDIA 显卡） cuda 或 cuda:0 算得快，但显存有限，模型太大装不下
    NPU（昇腾等加速卡） npu 部分国产设备，评测程序里也做了适配

    device_map="auto" 的意思是："放哪儿你（程序）自己看着办"。它会自动检查你机器上有哪些计算设备、各自还剩多少空间，然后把模型的各层合理地铺上去：有显卡就用显卡，显卡装不下就一部分放显卡、一部分放内存，只有 CPU 就全放 CPU。

    对你来说，这个参数的最大好处是"不用管硬件"：同一份代码，在没显卡的笔记本上和有显卡的机器上都能跑，不需要你手写 model.to("cuda")。

    必背

    考试里唯一要你记住的一句：模型有多少层、放哪个设备，是 device_map="auto" 自己安排的，你不能假设它在 CPU 上，也不能假设它在显卡上。所以后面把输入送进模型时，要写 .to(model.device) 让输入跟着模型走，而不是写死 .to("cuda")。

    torch_dtype=torch.float16：模型用什么精度¶

    计算机存小数有两种常见方式：float32（单精度，每个数字占 4 字节）和 float16（半精度，每个数字占 2 字节）。模型里每个参数都是一个小数，几百亿个参数按 float32 存，会非常占地儿。

    torch_dtype=torch.float16 就是要求：加载时把参数转成半精度。评测程序那句注释已经写得很清楚了——"使用半精度，显存占用减半"。

    精度 每个参数占用 适用场景
    torch.float32（默认） 4 字节 最准，最占地方，通常只在 CPU 或小模型上用
    torch.float16（半精度） 2 字节 考试推荐，显存/内存占用减半，速度更快

    算一笔账你就懂了：一个 6 亿参数的模型，用 float32 大约要 6 亿 × 4 字节 ≈ 2.4 GB，用 float16 只要约 1.2 GB。（这是"参数字节数"的粗略估算，实际占用还会加上一些额外开销，所以只能当作数量级参考。）对内存不大的考试机器来说，省下来的一半很关键。

    坑

    半精度会牺牲一点点数值精度。但在本考试的场景下（做四则运算、按格式输出），评测程序用的就是 torch.float16，你照着来就行，不要自己改成 float32——那会让显存/内存翻倍，可能直接跑不动。

    24.4　最小可运行的推理代码与逐行解释¶

    把前面三节拼起来，就是一段完整的、能跑的最小推理代码。它不是考试的提交代码（考试用的是 evaluate.py 里那套加载方式），而是一段"你自己在 LMCC-IDE 里新建一个 .py 文件就能验证概念"的练习代码。建议你亲手跑一遍，看着它打印出东西，比读十遍讲解都管用。

    # -*- coding: utf-8 -*-
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

# 1) 模型路径：和官方评测程序保持一致
model_name = "../Qwen/Qwen3-0.6B"

# 2) 加载分词器：文本  整数编号
tokenizer = AutoTokenizer.from_pretrained(
    model_name,
    trust_remote_code=True,
    padding_side="left",
    truncation_side="left",
)

# 3) 加载模型：半精度、自动安排设备
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    trust_remote_code=True,
    device_map="auto",
    torch_dtype=torch.float16,
)

# 4) 如果分词器没有定义 pad_token，就用 eos_token 顶替
if tokenizer.pad_token_id is None:
    tokenizer.pad_token = tokenizer.eos_token
model.config.pad_token_id = tokenizer.pad_token_id

# 5) 准备一段文本（这里直接写死，用来验证概念）
text = "你好，请用一句话介绍你自己。"

# 6) 文本 -> 张量
inputs = tokenizer(text, return_tensors="pt").to(model.device)

# 7) 生成：让模型接着往下猜
with torch.inference_mode():
    outputs = model.generate(
        input_ids=inputs["input_ids"],
        attention_mask=inputs.get("attention_mask"),
        max_new_tokens=64,
        do_sample=False,
        eos_token_id=tokenizer.eos_token_id,
        pad_token_id=tokenizer.pad_token_id,
    )

# 8) 张量 -> 文本
print("输出张量形状：", outputs.shape)
print("模型回答：", tokenizer.decode(outputs[0], skip_special_tokens=True))

    逐行拆解：

    • 第 1～2 行：# -*- coding: utf-8 -*- 是文件编码声明（官方源文件里都有，照抄即可）；import torch 让 PyTorch 可用，from transformers import ... 从 Transformers 库里取出两个类。这两句是所有推理脚本的开头。

    • 第 6 行：padding_side="left" 和 truncation_side="left" 是分词器的两个设置，第 25 章会专门讲为什么必须是 left。

    • 第 15～20 行：加载模型，device_map="auto" 交给程序自动安排，torch_dtype=torch.float16 半精度省一半空间。

    • 第 23～25 行：如果分词器没定义 pad_token（填充符号），就借 eos_token（结束符号）来用。这四行是"防御性代码"，不写的话批量推理时可能报错或出警告。

    • 第 28 行：text 就是"原始文本"。真实考试里它不是写死的，而是由 apply_chat_template_single(...) 拼出来的（第 26 章讲）。

    • 第 31 行：tokenizer(text, return_tensors="pt") 把文本变成张量字典，.to(model.device) 让这批数字搬到模型所在的设备上——模型在哪，输入就得在哪，这叫"同设备原则"。

    • 第 34～42 行：model.generate(...) 是核心。max_new_tokens=64 表示"最多再生成 64 个 token"；do_sample=False 表示贪心解码（每次都挑概率最高的，结果稳定不随机）；eos_token_id 和 pad_token_id 告诉它"结束符号长什么样、填充符号长什么样"。

    • 第 45 行：outputs.shape 打印出来是 torch.Size([1, 输入长度 + 新生成长度])。注意：它包含你的输入，这是第 38 章"答案串行"问题的根子。

    • 第 46 行：tokenizer.decode(outputs[0], skip_special_tokens=True) 把整数翻回中文，skip_special_tokens=True 顺手丢掉那些控制符号。

    坑

    如果你打印出来发现"模型回答"里把你的问题也重复了一遍，这不是 bug，这是正常的。outputs 里同时装着输入和新生成的内容。评测程序很懂这一点，它在解码时只取"新生成的部分"（第 38 章详讲）。你自己调试时如果只看最后一句，别慌。

    考试怎么考

    T1 例题的评分链路是：evaluate.py 加载模型 → 调你的 generate_single() 拿到 outputs → 评测程序自己数出输入长度 inp_len → 只解码 outputs[0][inp_len:] → 去掉 ... → 去掉 [Answer]: 前缀 → 比数字。所以你只需要保证"模型能生成出正确内容"，格式清洗的活儿评测程序替你干。

    本章要记住的 5 件事

    • 三个角色：分词器把文本翻译成整数，模型根据前文猜下一个整数，张量是它们之间搬运的数字包。
    • from_pretrained(模型名或路径, ...) 是加载模型的唯一入口；trust_remote_code=True 表示允许执行模型自带的代码。
    • device_map="auto" 让程序自己决定模型放 CPU 还是显卡，所以输入要写 .to(model.device)，不要写死 .to("cuda")。
    • torch_dtype=torch.float16 是半精度，占用减半，官方评测程序就是这么设的。
    • outputs 里包含输入，形状是 [batch, 输入长度 + 新生成长度]；考试中模型和分词器的加载由评测程序负责，你只写自己的函数。
