    第 26 章 对话模板的实现¶

    本章目标

    学完这一章，你能：① 说清 messages 列表怎么写；② 明白 tokenize=False 和 add_generation_prompt=True 各自管什么；③ 知道 enable_thinking（思考模式）是什么、什么时候开；④ 会打印拼好的字符串自己检查；⑤ 遇到常见报错能自己定位。

    第 19、20 章把"模型"和"分词器"讲完了。现在缺中间那一环：你手里只有一个 system prompt（系统提示）和一个题目字符串，怎么办成模型认识的样子？答案就是用 apply_chat_template。

    先解释"chat"（对话）这个词。现在的模型大多是对话模型，它期待你在给它输入时，按"谁在说话"的结构来组织：谁先交代规则（system）、谁在提问（user）、谁在回答（assistant）。这个结构写在一个叫"聊天模板（chat template）"的模板里，每个模型自带的模板不一样（因为是模型作者定制的）。你不能自己手拼这些格式，必须让分词器用它自己的模板拼，这就是 apply_chat_template 的职责：apply = 套用，chat template = 对话模板。

    26.1　messages 列表¶

    apply_chat_template 的第一个参数是一串"消息"，每条消息是一个小字典，只有两个关键：role（角色）和 content（内容）。看官方参考答案（T1 submission.py 原样）：

    messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": problem},
]
rendered = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
    enable_thinking=True,
)
return rendered

    逐行讲：

    • messages = [...]：一个列表，装着这次对话的"台本"。列表的顺序就是说话顺序。这里第一条是 system，第二条是 user。

    • {"role": "system", ...}：系统消息。它相当于"给模型的开场规矩"，用来交代身份和输出格式。在 T1 里，它就是 build_system_prompt() 返回的那段话（比如"你是一个精确的数学计算助手……使用格式 [Answer]: 数值"）。

    • {"role": "user", ...}：用户消息，也就是"小孩问的那道题"，来自 problem 参数。

    • rendered = tokenizer.apply_chat_template(...)：让分词器按这个模型的模板，把 messages 拼成一段完整文本，存进 rendered。

    • return rendered：函数的返回值就是这段文本。注意函数签名的返回类型标注是 str（字符串），所以这里绝不能返回别的东西。

    roles（角色）有哪几种¶

    role 中文 谁在说话、放什么
    system 系统 开发者/出题人定的规矩：身份、输出格式、注意事项
    user 用户 真实的问题、任务
    assistant 助手 模型的回答。你一般不用自己写；add_generation_prompt=True 会替你加上"轮到助手"的开头（下一节讲）

    坑

    两个最容易写错的地方：① role 和 content 的引号是英文双引号（"system"），中文引号会让 Python 直接报语法错；② 字典的键名必须拼对，是 content 不是 contents，是 role 不是 roles。这类错一犯，程序连跑都跑不起来，浪费考场时间。

    考试怎么考

    T1 要你实现的函数叫 apply_chat_template_single(tokenizer, system_prompt, problem)，返回 str。它的标准实现就是上面那段代码：把 system_prompt 和 problem 组成两条消息，交给 apply_chat_template 拼成文本。返回的一定是字符串，不是张量、不是编号——因为后面的 generate_single 拿到的参数名就叫 rendered_text，它会在里面自己做 tokenize。

    26.2　tokenize=False 与 add_generation_prompt=True¶

    这两个参数一开一关，正好相反，最容易记混。分开讲。

    tokenize=False：给我"文本"，先别急着翻译¶

    apply_chat_template 有两种输出方式：

    写法 返回什么 什么时候用
    tokenize=False 拼好的字符串（人看得懂的一段文本） 考试用法。因为函数要返回 str，后面再由 generate_single 统一 tokenize
    tokenize=True（默认） 整数编号（input_ids 那一套） 你自己写小脚本、想一步到位时可以用

    为什么考试必须用 False？因为题型把职责切开了：apply_chat_template_single 只负责"拼模板"，generate_single 负责"tokenize + 生成"。如果你在这里就 tokenize=True，返回的就不是字符串，而 generate_single 里又会对它做 tokenizer(rendered_text, ...)——把一个不是字符串的东西喂给分词器，程序立刻报错。

    必背

    tokenize=False = 只要文本，不要编号。看到函数签名写成 -> str，就已经说明了它必须配 tokenize=False。

    add_generation_prompt=True：把"轮到助手了"这句话也拼上¶

    对话模型的模板里，每段话外面都包着一些特殊的标记，用来告诉模型"这段是谁说的"。比如拼完的文本里会有类似 system、user 这样的记号（不同模型的记号长得不一样，所以不能手拼）。

    那模型怎么知道"该我说话了"？靠的就是模板最后那句"助手开头"。add_generation_prompt=True 的意思是：在拼好的文本末尾，再追加一句"轮到助手了"的引导（一般是 assistant 的开头标记）。模型读到这个开头，就会自然地往下续写答案。

    设置 拼出来的文本末尾 后果
    add_generation_prompt=True（考试用法） ……assistant（等着你说话） 模型接着这里往下写答案，正常
    不写，或 False ……用户的话就结束了 模型不知道轮到自己没有，可能又重复一遍问题、或干脆不回答

    坑

    忘了 add_generation_prompt=True，是"模型答非所问"最常见的原因之一。它的表现很典型：模型把你的题目又复述了一遍，或者接着"user"的腔调往下编问题，就是不给答案。遇到这种怪现象，先回头检查这个参数。

    26.3　enable_thinking 与思考模式¶

    第三个参数 enable_thinking=True，和 Qwen3 这类模型特有的"思考模式"有关，而且——它是 2025 真题解析里明确推荐的设置。

    什么是思考模式？简单说，模型在给出最终答案之前，会先写一段"内心独白"（推理过程），把步骤捋一遍，然后再输出正式答案。这段独白通常被包在 和 两个标记之间。

    模式 模型输出长什么样 优缺点
    思考模式 （enable_thinking=True） 先写一段 ……，再写正式答案 复杂任务更准；但更慢、更耗生成额度
    非思考模式 （enable_thinking=False） 直接输出答案，没有思考段 快；但稍复杂就容易错

    2025 年真题解析里对 T1「古诗词题目格式标准化」的推荐参数写得很清楚：enable_thinking 设为 True——开启思考模式，让模型在提取信息时更准确；max_new_tokens 设为 1024——给予足够的生成空间。并且特别提示：对于格式标准化任务，使用 do_sample 为 False（贪心解码）可以保证输出的稳定性，不需要随机性，确保每次对同样输入产生相同输出。

    考试怎么考

    把 2025 解析的推荐参数抄在脑门上：enable_thinking=True、max_new_tokens=1024、格式标准化任务 do_sample=False（贪心）。注意这和 T1 例题的评测程序 MAX_NEW_TOKENS=512、DO_SAMPLE=True 不同——例题和真题的参数是两套，考试时以当次评测程序里写死的常量为准，你的函数只要正确使用传进来的 max_new_tokens、do_sample 两个参数就行。

    技巧

    开了思考模式以后，输出会夹着 ...。别慌，评测程序会先 remove_thinking(raw_text) 把这段整段删掉，再提取答案（第 24、25 章详讲）。你要做的事只有一件：不要自己删,把模型原始输出原样返回给评测程序。

    坑

    enable_thinking 并不是所有模型都认的参数。它依赖模型自带模板里对"思考模式"的支持。如果你换了别的模型、报错提示 unexpected keyword argument 'enable_thinking'，那就说明这个模型的模板不支持它，去掉这个参数即可。考试用的是官方模型，按官方参考答案写就没问题。

    26.4　返回的字符串长什么样（打印出来看）¶

    光学参数不直观，最好的办法是打印出来看。下面这段小脚本，你可以在 LMCC-IDE 里跑一遍（把模型路径换成你的实际情况）：

    system_prompt = "你是一个精确的数学计算助手。"
problem = "12 + 35"

messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": problem},
]

rendered = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
    enable_thinking=True,
)

print("======= 拼好的文本 ========")
print(rendered)
print("==========================")
print("字符数：", len(rendered))

    打印出来的大致形状是这样（具体记号以你加载的模型模板为准，不同模型不一样）：

    system
你是一个精确的数学计算助手。
user
12 + 35
assistant

    从这段输出你能"看见"四件事：

    • 顺序：system 在最前，然后 user，最后是 assistant 的开头。这正好对应 messages 列表的顺序。

    • 包裹记号：每段话外面都包着 角色 和 `` 这类特殊记号。它们就是"谁在说话"的分隔线——正因为它们长得这么怪，才不能手拼，必须让模板生成。

    • 末尾的 assistant：这就是 add_generation_prompt=True 加上的"轮到助手了"。它后面什么都没有，等着模型接着写。

    • 没有其他杂东西：如果你看到这里还夹着别的格式，说明参数没设对，回去逐项检查。

    技巧

    考场调试时，在 apply_chat_template_single 里临时加一句 print(rendered)（交卷前记得删掉），再跑演示模式。你会看到拼好的完整文本，一眼就能判断 system prompt 有没有生效、题目有没有放进去、末尾有没有 assistant 引导。Visual Studio Code 的终端里，这一步通常比瞎猜快十倍。

    26.5　常见报错与解决¶

    这一节是"急救包"。下表是按"症状 → 原因 → 怎么改"整理的。

    报错或症状 真实原因 怎么改
    TypeError: 'NoneType' object is not iterable 出现在模板里 某个参数是 None，最常见的是 system_prompt 为空（build_system_prompt() 忘了写、或者写着 pass） 先把 build_system_prompt() 实现好，返回一段非空字符串
    TypeError: ... got an unexpected keyword argument 'enable_thinking' 这个模型的聊天模板不支持思考模式开关 去掉 enable_thinking=True；考试用官方模型时不要去掉
    返回的东西不是字符串，generate_single 里报错 漏写了 tokenize=False，返回的是编号而不是文本 补上 tokenize=False
    模型不回答，反而把题目重复了一遍 漏写了 add_generation_prompt=True 补上 add_generation_prompt=True
    SyntaxError，指向 messages 那一行 用了中文引号、中文逗号，或者括号没配平 全部换成英文半角符号，重新数一遍括号
    模板里出现 {{ ... }} 或 UndefinedError 参数的键名拼错了（比如写成了 contents） 逐字核对 role 和 content 两个键名

    考试怎么考

    评测程序在加载模型之后，还会做一次预检：assert len(sp) > 0, "system_prompt 为空，请在 submission.py 中实现 build_system_prompt()"。也就是说，如果你的 build_system_prompt() 没写好，评测程序会在真正做题之前就停住并给出这句提示。看到这句话，不用怀疑别的地方，直接去补 build_system_prompt()。

    本章要记住的 5 件事

    • messages 是"对话台本"列表，每条是 {"role": ..., "content": ...}，顺序就是说话顺序，常用 role 是 system / user / assistant。
    • tokenize=False 表示"只给我拼好的文本"，因为考试要的函数返回类型是 str。
    • add_generation_prompt=True 会在末尾补上"轮到助手"的引导；漏了它，模型容易复述题目而不作答。
    • enable_thinking=True 开启思考模式，输出中会夹 ...；2025 解析对 T1 推荐它，并推荐 max_new_tokens=1024、格式任务 do_sample=False。
    • 参数不确定就打印拼好的字符串：顺序、包裹记号、末尾 assistant 引导，一眼就能验收。
