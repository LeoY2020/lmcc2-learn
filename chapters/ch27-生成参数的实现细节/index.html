    第 27 章 生成参数的实现细节¶

    本章目标

    学完这一章，你能：① 把 T1 官方参考答案里的 generate_single() 原样写出来；② 逐行说清 tokenize、.to(model.device)、model.generate 的每个参数；③ 明白返回值的形状各维代表什么；④ 知道 torch.inference_mode() 和 no_grad 是什么、为什么生成时要加。

    前面三章把"零件"讲完了：加载模型、分词器关键词、聊天模板。这一章开始把零件装成一台机器。先从单条推理入手——它简单、好懂，而且它是批量推理的基础。

    先把"单条推理"的场景说清楚：一次只做一道题。评测程序阶段一有 8 道题，就是一道一道地调 generate_single。它对应你写函数时最需要关心的三件事：输入怎么变成张量、生成参数怎么给、返回值长什么形状。

    27.1　官方参考答案原样代码¶

    下面是 T1 参考答案 submission.py 里的 generate_single()，原样引用（只把注释保留，没有改动任何一行逻辑）：

    def generate_single(
    model: AutoModelForCausalLM,
    tokenizer: AutoTokenizer,
    rendered_text: str,
    max_new_tokens: int,
    do_sample: bool,
) -> torch.Tensor:
    # ======== 考生实现区域（可修改） ========

    # 1. tokenize 输入
    inputs = tokenizer(rendered_text, return_tensors="pt", padding=True).to(model.device)

    # 2. 生成输出
    outputs = model.generate(
        input_ids=inputs["input_ids"],
        attention_mask=inputs.get("attention_mask"),
        max_new_tokens=max_new_tokens,
        do_sample=do_sample,
        eos_token_id=tokenizer.eos_token_id,
        pad_token_id=tokenizer.pad_token_id,
    )

    return outputs

    # ======== 考生实现区域（可修改） ========

    只有 8 行有效代码，但每一行都值得讲。我们一段一段来。

    27.2　逐行讲：tokenize 与 .to(model.device)¶

    inputs = tokenizer(rendered_text, return_tensors="pt", padding=True).to(model.device)

    这一行干了三件事，用"点号链"连在一起，从左往右按顺序执行：

    这一小段 它做什么 为什么这么写
    tokenizer(rendered_text, ...) 把上一章拼好的文本变成"数字字典"，里面有 input_ids、attention_mask 等 模型只认整数，必须先翻译
    return_tensors="pt" 指定用 PyTorch 张量的格式返回（pt = PyTorch） 不写的话返回普通列表，模型不能直接用
    padding=True 允许补齐长度 单条时其实补不出东西（只有一条，本身就是最长），但保留它能让代码在单条/批量两种场景下写法一致
    .to(model.device) 把张量搬到模型所在的那块设备上 输入和模型必须在同一台设备上，否则 PyTorch 报错

    必背

    为什么写 .to(model.device) 而不是 .to("cuda")？因为模型放哪儿是 device_map="auto" 决定的，可能在 CPU、可能在 GPU、也可能在 NPU。model.device 会自动告诉你"模型现在在哪"，输入跟着它走，代码就能在各种机器上都跑通。写死 "cuda" 的话，没有显卡的机器上直接报错。

    顺便说一句 inputs 是什么类型：它是一个类似字典的对象（Transformers 里叫 BatchEncoding），可以像字典那样用方括号取值，也能用 .get() 取值。所以下一段出现了 inputs["input_ids"] 和 inputs.get("attention_mask") 两种写法——前者是"一定有，直接取"，后者是"可能没有，取不到给 None"，这就是第 30.4 节讲的防御式写法。

    坑

    不要在 submission.py 里对输入做任何"截断、删减、重新包装"。官方要求写得很清楚：直接返回模型原始输出，不要做后处理，也不要在函数里做答案提取。你要是自己把数字抠出来再返回，评测程序会拿到一个形状不对的张量，解码就崩了。

    27.3　逐行讲：model.generate 的参数¶

    outputs = model.generate(
    input_ids=inputs["input_ids"],
    attention_mask=inputs.get("attention_mask"),
    max_new_tokens=max_new_tokens,
    do_sample=do_sample,
    eos_token_id=tokenizer.eos_token_id,
    pad_token_id=tokenizer.pad_token_id,
)

    model.generate(...) 是整个考试的心脏。它接收输入编号，一个 token 一个 token 地往下猜，最后给你一整串编号。6 个参数，逐个说"设成什么、为什么"：

    参数 设成什么 为什么
    input_ids inputs["input_ids"] 真正的输入内容，一串整数编号。这是必填项
    attention_mask inputs.get("attention_mask") 告诉模型哪些位置是真实内容、哪些是填充位
    max_new_tokens 函数传进来的 max_new_tokens 最多新生成多少个 token。注意它限制的是"新生成"的部分，不是整段总长度。 例题评测程序给的是 512；2025 真题解析对 T1 推荐 1024
    do_sample 函数传进来的 do_sample True = 按概率随机抽（采样）；False = 每步都挑概率最高的（贪心）。 例题评测程序是 DO_SAMPLE=True；2025 解析对格式标准化任务推荐 False
    eos_token_id tokenizer.eos_token_id 告诉它"遇到结束符就停"。不写可能一直生成到上限，白等
    pad_token_id tokenizer.pad_token_id 批量生成时填充位的编号。不写容易出警告、甚至报错

    有两个地方必须提醒：

    第一，max_new_tokens 和 do_sample 不要写成死数，要用函数参数。函数签名里之所以有这两个参数，就是因为评测程序要根据情况传不同的值（比如例题传 512/True，真题可能传 1024/False）。你要是写死成 max_new_tokens=512，就等于把评测程序的控制权抢走了，换一套数据就可能出问题。

    第二，do_sample=False 时不要传 temperature、top_p 之类的参数。贪心解码本质上是"每步只挑第一名"，那些采样参数对它没有意义。Transformers 收到这种组合还可能给你警告。考试里按参考答案的六个参数写，一个不多一个不少，最稳。

    考试怎么考

    T1 例题评测程序里的常量是：MAX_NEW_TOKENS = 512、DO_SAMPLE = True，并且这两个值会作为实参传进你的 generate_single() 和 generate_batch()。真题解析里 T1 的推荐是 max_new_tokens=1024、格式标准化 do_sample=False（贪心）。结论：函数里老老实实转发这两个参数，不要写死任何数字。

    27.4　返回值的形状含义¶

    return outputs 返回的是一个二维张量，形状写成：

    [批大小, 输入长度 + 新生成的 token 数]

    逐维解释：

    • 第 0 维：批大小。单条推理时是 1，因为一次只有一道题。批量推理时会等于那一批的条数。

    • 第 1 维：总长度。注意——它包括你送进去的输入。假设输入有 40 个 token，模型新写了 20 个 token，那这一维就是 60。

    再具体一点：outputs[0] 取的是第 0 条数据，也就是完整的一串编号；outputs[0][40:] 才是"新生成的那 20 个"。这个"输入 + 新生成"的拼接结构，就是第 38 章要讲的"答案串行"问题的总根源。

    写法 含义 典型用途
    outputs.shape 整个张量的形状 调试时看"生成了多长"
    outputs[0] 第 0 条数据的完整编号串 交给 decode 还原文本
    outputs[0][inp_len:] 第 0 条数据里"新生成"的部分 评测程序就是这么切出答案的
    outputs[:, inp_len:] 所有条数据的新生成部分 批量解码时可以这么切

    坑

    不要返回 outputs[0]（一维），也不要返回 tokenizer.decode(...)（字符串）。函数的返回类型标注是 torch.Tensor，评测程序会拿它做切片和拼接。返回值少一维或类型不对，后面全崩。

    27.5　torch.inference_mode() 与 no_grad¶

    现在讲那个"包在外面的括号"。在评测程序里，你的 generate_single 是被这样调用的：

    with torch.inference_mode():
    for idx, (problem, gold) in enumerate(stage1_items, 1):
        raw_text = solve_single(model, tokenizer, problem, MAX_NEW_TOKENS, DO_SAMPLE)
        ...

    背景先说清楚。PyTorch 做神经网络运算时，默认会记录每一步的运算过程，用来事后算梯度（梯度是训练时更新参数用的方向信息）。可我们是在推理（inference），不做训练，根本不需要梯度。于是 PyTorch 提供了两种"省着点"的写法：

    写法 含义 特点
    with torch.no_grad(): 不计算梯度 经典的省内存写法，到处都能用，最保险
    with torch.inference_mode(): 推理模式：更彻底地关掉梯度相关记录 更省内存、通常更快；官方评测程序用的就是这个

    一句话理解它们：no_grad 是"这次别记笔记了"，inference_mode 是"这次是纯做题，笔记和回溯都不需要，直接最省模式跑"。考试里你不用自己写——评测程序已经在外面包好了。但你要知道它存在，因为：

    • 你自己写调试脚本时，应该照着包一层，尤其是显存/内存紧张的时候；

    • 如果你在 inference_mode() 里试图做"训练、改参数"的操作，会直接报错——它明确告诉 PyTorch"这是推理，不许改"。这正好保护了考试环境。

    技巧

    在你自己的调试脚本里写 with torch.inference_mode(): 包住 model.generate(...)。这不会改变答案，只是省内存。考试机器内存有限，包上它有时候就是从"跑不动"到"跑得动"的差别。

    考试怎么考

    注意一个细节：评测程序是在 torch.inference_mode() 里调用你的函数的（阶段一和阶段二都是）。所以你的函数内部不需要再包一层，包了也不出错；但反过来说，你不能指望在函数里做任何"需要梯度"的操作。老老实实只做 tokenize → generate → return 三件事。

    本章要记住的 5 件事

    • 单条推理三步：tokenizer(...) 变张量、model.generate(...) 生成、return outputs 原样返回。
    • tokenizer(rendered_text, return_tensors="pt", padding=True).to(model.device)：转张量 + 跟着模型走设备。
    • generate 的六个参数：input_ids、attention_mask、max_new_tokens、do_sample、eos_token_id、pad_token_id；前两个必须用函数传进来的值转发。
    • 返回值形状 [批大小, 输入长度 + 新生成长度]，包含输入；outputs[0][inp_len:] 才是新答案。
    • torch.inference_mode() 是官方评测程序用的"纯推理模式"，关掉梯度记录、更省内存；不需要你在函数里自己写。
