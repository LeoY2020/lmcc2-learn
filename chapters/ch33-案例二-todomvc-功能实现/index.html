    第 33 章 案例二：TodoMVC 功能实现¶

    本章目标

    学完这一章，你能：① 把「保留原功能、四种科目、行内科目、联合筛选、可见移动、按钮边界、刷新保存、性能限制」八条要求，各用自己的话复述一遍；② 对每一条都能说出平台最可能怎么测它；③ 一听到「同名作业」「隐藏条目」「全清单未完成数」就知道坑在哪里。

    先给这道题一个总体的画面。项目是一个 TodoMVC 小网页：一个输入框，输入作业标题按 Enter 就加一条；每条作业前面有勾选框，后面有删除按钮；底部有「全部 / 未完成 / 已完成」三个筛选链接、一个「清理已完成」按钮和一个剩余数量。中文里 Todo 就是「待办事项」，MVC 是一种把数据（Model）、界面（View）、控制逻辑（Controller）分开放的代码组织方式——这三部分恰好对应你说话时要区分清楚的三件事：清单里的数据、屏幕上看得见的行、点一下按钮之后发生什么。本部分会反复用这三层来思考。

    初始项目缺什么？缺三块：每条作业没有「科目」，行内虽然有科目下拉框但选了不生效；顶部虽然有科目筛选下拉框，但选了不过滤；每条虽然有「上移」「下移」两个按钮，但点了不动。另外数据只放在内存里，刷新就没了。你的任务，就是通过跟 Agent 对话，把这三块补上，同时不破坏原有的四件事（添加、勾选、删除、清理）。

    下面八条要求，就是平台打分的全部依据。注意一句关键的话：隐藏点只检查题面已写出的行为。这句话是给你吃的定心丸——隐藏点不会考「题面没说的功能」，所以八条要求背熟，就等于把 100 分的地图拿在手里了。

    33.1　要求一：原有功能一条都不能坏¶

    第一条可以理解成「不许拆房子」：你新加的科目标签、移动按钮、保存逻辑，都要搭在原来的功能上，而不能把原来能用的东西弄坏。原功能拆开有八件小事，我们一件一件过。

    原功能 精确含义 常见破坏方式
    Enter 添加 在 .new-todo 输入框里按 Enter 就添加一条，输入框随即清空 为了做筛选而重写渲染，把按键监听弄丢，按 Enter 没反应
    去掉首尾空白 标题先去掉两端的空格再使用；中间的空格保留 忘了去空白，或把中间空格也一起删掉
    空标题不添加 去掉首尾空白后是空串（例如只输入 3 个空格），什么都不做 先判空再去空白，导致空格串被当成有效标题加进去
    同名是不同条目 标题相同的两条作业是两条独立数据，各有各的科目、完成状态、位置 用标题当唯一标记，改一条科目结果两条都变
    单独勾选 / 取消 每条的 .toggle 勾选框只改这一条的完成状态 勾选框被重绘后事件绑定丢了，或者删掉旧节点没重新绑
    删除 行的 .destroy 按钮只删这一条 在筛选视图下用「可见序号」去删全清单里的同序号条目
    清理已完成 .clear-completed 删掉全清单里所有已完成条目，包括当前看不见的那些 只删可见的已完成条目
    三种完成筛选 + 剩余数 全部 / 未完成 / 已完成三个筛选继续有效；.todo-count strong 里的数字永远是全清单未完成条数 把剩余数算成「当前可见的未完成条数」

    上一张表里最后一行那个坑，是全题最容易失分的地方之一。为什么剩余数要「全清单」？因为 TodoMVC 原本的语义就是「你还有几件事没做完」，它跟你在看哪个筛选没有关系。公开点 P01-2 专门测了这一点：切到「数学」科目筛选以后，页面上只看得见两条未完成作业，但此刻剩余数仍然要显示 2，因为它算的是全清单。假设全清单是「预习语文（未完成 / 数学）、数学订正（已完成 / 英语）、英语阅读（未完成 / 数学）」，那么无论你切到哪个科目、哪个完成筛选，剩余数都应该是 2。

    坑

    很多人一看到「筛选」就顺手把剩余数改成「当前可见的未完成数」。这在数学视图下会算出 2（碰巧对了），可一旦再看「已完成」，可见的未完成数就变成 0，立刻错。正确做法：剩余数只用一个公式——全清单里 completed 为 false 的条目数量。渲染多少次都不会错，因为它根本不看筛选条件。

    再说「同名条目」。题面里「同名作业是不同的条目」这句不是废话，它是给第二种坑打预防针：标题不是身份证。公开点 P02-2 就演了这一幕——先输入「朗读」，再输入一次「朗读」，页面出现两条一模一样的行；然后先把第 2 行设为数学，再勾选第 1 行，最后把第 1 行改成英语。预期结果是「朗读（已完成 / 英语）」和「朗读（未完成 / 数学）」各在各位。如果代码里用标题去定位条目，这两条就会互相串台，整个子场景全错。

    技巧

    跟 Agent 说话时，不要只说「要支持同名作业」，更有效的说法是给出机制：「每条作业用唯一 data-id 标识，所有操作（改科目、勾选、删除、移动）都按 data-id 定位到全清单里的那一条，不要用标题定位。」你把「用什么定位」说清楚，Agent 就很难写错。

    33.2　要求二：四种科目，新作业一律未分类¶

    第二条定义了一套可选项：每条作业有四种科目——未分类、语文、数学、英语。它的英文取值（平台用来定位控件的值）是 unassigned、chinese、math、english；页面上给用户看的中文文案是「未分类 / 语文 / 数学 / 英语」。这两者可别混：一个给程序看，一个给人看。

    接着是三个「一律」：

    • 新作业一律是未分类；
    • 新作业一律是未完成；
    • 新作业一律追加到全清单末尾。

    要求二里的「追加到末尾」看起来理所当然，其实藏着一个非常隐蔽的分支。想象你正在「只看数学」的视图里，此时输入一条新作业按 Enter：新作业的科目是未分类，它跟当前的科目筛选不匹配，所以它不会出现在你眼前的列表里——但它在全清单里确确实实被加到了最后。公开点 P05-1 第 14～16 步就是这一幕：切到「数学」筛选，输入「听写」按 Enter，页面保持只有「代数」一条；再切回「全部科目」，才看到「听写（未完成 / 未分类）」排在最后。

    考试怎么考

    平台用的是操作 + 观察页面的方式：它按 data-id 或可见行序号操作，然后对着「可见行依次为……」这段文字逐行核对标题、完成状态、科目。所以「输入了但看不见」这件事，平台是通过「切到全部科目后它出现在末尾」来验证的。你如果为了「让用户看到」而把新作业自动归成当前筛选的科目，这一步就错了，而且违反题面明写的「即使正在只看数学，也不把新作业自动归为数学」。

    新作业要落成的样子 取值 为什么
    科目 unassigned（未分类） 题面明写「新作业一律是未分类」，与当前筛选无关
    完成状态 未完成 题面明写「未完成」
    在全清单里的位置 数组末尾 题面明写「追加到全清单末尾」；至于它在当前视图里看不看得见，由筛选决定

    33.3　要求三：行内科目下拉框只改这一条¶

    每一行的科目下拉框是 select.task-subject，它有四个选项（未分类、语文、数学、英语），并且当前显示的就是这条作业现在的科目。你把它改成数学，预期是：

    • 这一条的科目变成数学；
    • 它的标题不变、完成状态不变；
    • 其他条目的科目不变，全清单顺序不变；
    • 它如果不再符合当前筛选，就立刻从当前视图消失。

    第四条最容易被忽略，但它有公开测试点兜着。公开点 P03-1 第 9～12 步：科目筛选设成「数学」、完成筛选设成「未完成」，此时可见的只有「算术（未完成 / 数学）」一条；平台把可见第 1 行（序号 0）的科目改成英语，预期是「可见列表为空」——因为它不再是数学作业了，而当前筛选只看数学。紧接着第 13 步检查「所有移动按钮的边界状态」，在当前可见列表为空的情况下，结论是「没有需要检查的移动按钮；边界检查通过」。

    注意这里冒出来一个新概念：可见列表为空。它不是「作业都没了」，而是「存在，但一条都不符合当前筛选」。这两件事必须分清：全清单里可能还有 4 条作业，只是这个筛选下一条都不显示。

    坑

    改完科目「这一条应该消失」，最省事的实现是重新按当前筛选渲染一遍整份列表，而不是去给那一行加个 class 把它藏起来。因为如果只是藏起来，虽然它确实不算可见行了，但很容易出现另一种错：只把这一行藏了，却没有重新计算其余行的上移、下移按钮状态，导致新的第一条还拿着「上移」可以点。所以记一句话：凡是改变了可见集合的操作，都要重渲染 + 重算按钮状态。

    还有一个关于控件本身的小细节。每一行都有自己的科目下拉框，两条同名作业各有一个，它们的取值互不干扰。如果 Agent 图省事，用一个全局变量记录「当前选中的科目」，那么改第 2 行的科目时第 1 行可能跟着变。判断一个实现对不对，有个很简单的方法：改一行，看看同名的另一行有没有变化。

    技巧

    第一次跟 Agent 提科目功能时，建议连这句话一起说：「行内科目下拉框的 value 分别是 unassigned / chinese / math / english，修改它时只更新全清单里对应 data-id 那一条的 subject 字段，然后整体重新渲染。」一句话同时锁住了「按 id 定位」「只改一个字段」「改完重渲染」三件事。

    33.4　要求四：顶部科目筛选与完成筛选同时生效¶

    第四条是把两把筛子叠在一起。顶部的科目筛选有三件事要记住：

    • 它是一个下拉框，控件是 select#subject-filter，取值 all（全部科目）、unassigned、chinese、math、english，一共五个选项；
    • 它和底部的完成筛选（.filters a，三个链接 #/、#/active、#/completed）同时生效，是「并且」的关系，不是「或者」；
    • 切换任何筛选都不改变作业本身，也不改变全清单顺序，只是决定谁显示出来。

    「同时生效」的正确判断只有一个式子，记住它就能写出对的代码：一条作业可见 ⟺ （科目筛选为全部 或 该条科目等于科目筛选值）且（完成筛选为全部 或 该条完成状态等于完成筛选值）。任何一个条件不满足就不显示。所谓「数学 + 未完成」只显示未完成的数学作业，用中文说就是这个式子。

    科目筛选 完成筛选 可见的是
    全部科目 全部 全清单所有条目，按全清单顺序
    数学 全部 所有数学作业，不论完成与否
    数学 未完成 数学且未完成的作业
    数学 已完成 数学且已完成的作业
    未分类 未完成 还没选科目、也还没做完的作业
    英语 全部 所有英语作业

    为什么题面要专门写「切换任何筛选都不改变作业或全清单顺序」？因为这是两个完全不同的操作：筛选只是改变「看哪些行」，排序是改变「行与行的先后」。如果你偷懒用「把不匹配的行删掉、把匹配的排到前面」来实现筛选，那么切一次筛选就永久改动了数据，切回去以后顺序全乱。正确的模型永远是：全清单是唯一的真相，筛选只是视图。

    技巧

    把这句话原文念给 Agent 听，效果非常好：「请把数据结构保持为一份全清单数组；筛选只影响渲染时显示哪些行，绝不修改数组内容或顺序。」Agent 听懂了这一句，「筛选择序不变」这一类错就基本不会犯。

    考试怎么考

    公开点 P03-1 把两把筛子来回切了多次（第 9 步数学+未完成、第 14 步已完成、第 15 步未分类、第 16 步英语、第 17 步完成改全部、第 18 步科目改全部），每一步都列出了完整的可见行。这说明平台对「组合筛选」的检查是穷举式的：你想靠碰运气蒙对几乎不可能，只有把那个「且」写对才行。

    坑

    两个筛选的取值容易记混：科目筛选的「全部」是 all，完成筛选的「全部」是链接 #/。它们来自两个不同控件，一个用下拉框选择、一个用链接点击。别把 all 当成完成筛选的值，也别指望完成筛选是个下拉框——平台是按 .filters a 里的链接去点的。

    33.5　要求五：上移、下移只与当前可见的相邻项交换¶

    第五条是全题的灵魂，也是最容易理解错、最容易做错的一条。先把原话抄一遍：「上移只与当前可见的上一条交换，下移只与当前可见的下一条交换。交换的是这两条在全清单中的位置，其他条目的位置保持，作业的标题、完成情况、科目跟着它本人走。」

    这段话里有两个「交换」要区分清楚：交换对象不是全清单里紧挨着的那一条，而是当前可见的上一条 / 下一条；交换内容是这两条在全清单数组里的下标，也就是两条作业的数据对象（含唯一 id、标题、完成状态、科目）整个换位置，而不是只交换标题字符串。

    题面给的那个例子，请你跟着走一遍，走完就懂了：全清单依次是 A（数学）、B（英语）、C（数学）、D（未分类）。只看数学时可见的是 A、C。现在点 C 的「上移」：

    操作前 全清单：[A(数学), B(英语), C(数学), D(未分类)]
                 数学视图可见：[A, C]

点 C 的上移 -> 找到 C 在数学视图里的上一条 = A
             -> 交换 A 与 C 在全清单里的位置

操作后 全清单：[C(数学), B(英语), A(数学), D(未分类)]
                 数学视图可见：[C, A]

    看到了吗？B 和 D 一动没动，它们还在原来的绝对位置上；A 和 C 的位置对调了，各自带着自己的科目跟走。这就是「交换的是全清单位置」。再点 C 的「上移」就没有用了——它现在已经是数学视图里的第一条，要求六规定它必须禁用。

    33.11　「可见行」的定义与序号从 0 开始¶

    必背

    可见行 = 当前页面上、按真实页面顺序排列的那些作业行。平台按这个顺序编号，从 0 开始：序号 0 表示第一行。题面里说的「可见第 3 行（序号 2）」就是这种数法。

    准确的直觉是：序号不是存在数据里的，它是每次看页面时临时数出来的。同一个条目在「全部科目」里可能是序号 2，切到「数学」之后可能变成序号 0。数据没变，序号变了。

    筛选状态 可见行依次为 「数学练习（英语）」那条的可见序号
    全部科目 + 全部 0. 数学练习（数学）；1. 背单词（未分类）；2. 数学练习（英语） 2
    未分类 + 全部 0. 背单词（未分类） 不在可见行里
    英语 + 全部 0. 数学练习（英语） 0

    这张表说明两件事：① 平台的「第几行」永远指当前可见顺序；② 代码不能用可见序号当数据身份，只能用 data-id。

    题面还给了一句关键的话：「可移除不匹配筛选的行，也可用 CSS 隐藏。平台只按可见行判断顺序。」 也就是说：不匹配的行，删除或用样式藏起来都行，平台只看「看得见的那些行」的顺序。所以「可见」＝不被样式隐藏、也不被删除。三条判断规则：① display:none 或被删掉的行不算可见行；② 只是颜色变淡、仍显示在页面上的行，平台仍算可见行（所以不要用变淡表示禁用）；③ 一条都不匹配时可见行数为 0，题面预期的文字是「可见列表为空」并补一句「没有需要检查的移动按钮；边界检查通过」。

    • 如果一行被设置了 display:none（或者被从页面里删掉了），它就不算可见行，不占序号；
    • 如果一行只是「颜色变淡」「加了禁用样式」但它仍然显示在页面上，平台还是把它当可见行；
    • 如果当前筛选下一条都不匹配，那么可见行数就是 0，页面上没有行，但页面本身必须正常、科目筛选仍可用。

    33.12　可隐藏、但必须保留的东西¶

    18.2 说了「可以隐藏」，这一节说清「隐藏的边界在哪里」。题面把允许做的事和必须做的事分得很清楚，我们分两栏看。

    允许你做的 必须遵守的
    移除不匹配当前筛选的行 移动按钮禁用时仍要显示在行内（不能藏、不能删）
    用 CSS 隐藏不匹配的行 正常操作需要的控件必须可见、可用
    自由安排布局、配色、内部函数、保存格式 科目和按钮的文字要能辨认
    在 src/ 与 assets/ 里新增源码和样式文件 保留平台用来定位控件的 class 名与 id

    先把「必须保留」的三句话拆开讲。

    第一句：移动按钮禁用时仍要显示在行内¶

    当某条作业是当前可见的第一条时，它的「上移」按钮要处于禁用状态——但禁用的意思是不让点，不是不让看。按钮必须还在那一行里，只是带上 disabled。如果在第一条上干脆不渲染上移按钮，平台就会找不到 button.move-up，直接判定这一步不成立。

    这也解释了为什么「原生 disabled」值得反复强调：它天生就是「看得见、点不动」的状态，一举两得。

    第二句：正常操作需要的控件必须可见、可用¶

    「可见」指它没有被隐藏；「可用」指它没有处于禁用状态（除非边界规则要求它禁用）。换句话说，不该禁用的按钮不能禁用，不该藏起来的控件不能藏。反面例子：把「删除」按钮做成只有鼠标移上去才显示，平台测试很可能点不到；把「清理已完成」在列表为空时隐藏掉，而题面要求它一直可用。

    还有一个很实际的细节：科目和按钮文字要能辨认。如果按钮文字变成图标、颜色太浅、字号太小导致辨认不了，都可能被判为不可用。最安全的做法：按钮上直接写中文「上移」「下移」，科目下拉框的选项直接写「未分类」「语文」「数学」「英语」，并按给定的 value 取值。

    第三句：选择器不能变¶

    判断一个改动安不安全，可以问自己：「平台还能不能像原来那样找到这个控件？」 如果 Agent 把 class="todo-list" 改成了 class="task-list"，或者在列表和目标之间加了包装层，答案就是不能。这类改动必须在对话里明确禁止。

    技巧

    有一句「防拆家」的话，建议第一次对话就发给 Agent：「请保留 .new-todo、.todo-list 的直接子元素 li（带唯一 data-id，标题在 label 内）、.toggle、.destroy、.clear-completed、.todo-count strong、.filters a（#/ #/active #/completed）、select#subject-filter、select.task-subject、button.move-up、button.move-down 这些选择器和它们的取值；移动按钮的边界用原生 disabled 属性。」

    坑

    「用 CSS 隐藏不匹配的行」有两个连带的注意点。第一，被隐藏的行虽不算可见行，但它还留在页面上；如果某段逻辑用「页面上一共有几个 li」判断边界，就会多算，必须改成用可见行数组判断。第二，隐藏行的按钮状态会在它重新可见时被平台读到，所以每次渲染都要按当次可见顺序把所有行的按钮状态一起算对。

    考试怎么考

    公开点里有好几种「空列表」状态：P01-1 第 9 步删除后、P01-2 第 10 步「已完成」筛选下、P03-1 第 12 步改完科目后、第 15～16 步筛选后，预期都是「可见列表为空」。它们都要求页面正常、科目筛选仍可用、没有报错。所以「空」也是一种必须被正确处理的状态。

    33.13　只有对话能改代码¶

    这一节讲清楚「谁在动手改代码」。理解这个问题，你就不会出现「我偷偷去改一下」的念头，也不会浪费时间去找不存在的入口。

    Agent 具备三个工具：read_file、write_file、bash。 它们是 Agent 的手：读文件、写文件、执行项目内的命令。你用中文描述需求，Agent 用这三个工具去读代码、改代码、跑命令。

    考生不能使用编辑器、命令行或外部工具。 这是本部分最硬的一条纪律。你不能打开文件编辑器改一个字，不能开终端敲命令，也不能用别的工具直接改代码或测试内容。你唯一能做的，是在对话框里打字。

    为什么这样设计？因为这道题考的是「把需求讲清楚、把验收标准定明确」，而不是「手速」。所以把心态从「我要写代码」切换成「我要当一个小项目的产品经理 + 验收员」：

    角色 该做的事 不该做的事
    产品经理（你） 说清要什么行为、给出操作与预期的例子、排优先级 自己开文件去改代码
    工程师（Agent） 读相关文件、按指令改代码、跑项目内命令、汇报改了什么 自行发挥加功能、改题面或测试
    验收员（你） 看页面预览、核对可见行、比对操作是否生效 凭感觉说「应该好了」就不再检查

    必背

    两条配套规则：① 模型和 Agent 的配置由考场统一提供，不开放切换——本题用的模型是 Qwen3.5-35B-A3B，Agent 是考场极简编程 Agent（单 Agent）；② 你可以查看平台提供的页面预览、文件变化和用量记录——页面预览看功能对不对，文件变化看 Agent 动了哪些文件，用量记录看还剩多少 Token。

    考试怎么考

    考试的约束是这样一串数字：每次模型输出最多 8,192 Token；每条学生消息最多触发 4 次模型请求；整题最多 80 次请求；单条工具命令最长 60 秒；作答时间本版 40 分钟。「只能对话」既是规则，也决定了你必须把话说在点子上。第 30 章会把这份预算拆成时间表和 Token 账本。

    33.14　评分：公开 5 点 + 隐藏 5 点，每点 10 分¶

    总分 100 分的功能分，由 10 个测试点组成，每个点 10 分：

    组别 点数 分值 什么时候运行 现场能看到什么
    公开点（P01～P05） 5 点 每点 10 分，共 50 分 点击提交后自动运行 每点的实际结果、预期结果及差异都展示
    隐藏点 5 点 每点 10 分，共 50 分 考试结束后统一评测 输入、操作、预期和成绩在考试时完全不展示

    最重要的规则是这一句：「每点包含两个独立子场景，所有操作和预期全部通过才得 10 分；不按单条断言给部分分。」 它有三层含义：

    • 一个点里没有「部分分」：20 个步骤里过了 19 个，还是 0 分。
    • 同一个场景内的操作是连续的：「每个子场景使用独立浏览器环境，从空白清单开始；同一场景内按顺序连续操作」。第 5 步留下的状态会带到第 8 步。
    • 隐藏点只检查题面已写出的行为：不会考你没见过的新功能，所以把八条要求都实现对就够了。

    这三点合起来指向一个具体策略：把力气花在「小步骤的正确性」上，而不是花在「功能的丰富度」上。 你在预览里验收时，也应该按「连续操作」的方式走，而不是每步刷新重来。

    • 平台自动运行 5 个公开测试点，现场展示实际结果与预期结果及差异。你不需要点击「运行测试」、不需要输入测试命令。公开功能分满分 50。

    坑

    隐藏点虽然不展示，但它只检查题面已写出的行为。这条既是安慰也是要求：不要为「防隐藏点」去发明功能，但也不能只针对公开点的具体数据写死逻辑，比如不能把所有逻辑写成「如果标题是数学练习就……」。

    本章要记住的 7 件事

    • 控件名和 id 是你和平台之间唯一的公共语言：.new-todo、.todo-list > li（每行唯一 data-id、标题在 label）、.toggle、.destroy、.clear-completed、.todo-count strong、.filters a、select#subject-filter、select.task-subject、button.move-up / button.move-down。
    • 每行必须是列表容器的直接子元素 li，不能加中间包装层；每条必须带唯一 data-id。
    • 「可见行」＝当前页面上按真实顺序排列的作业行，序号从 0 开始；被删除或被 CSS 隐藏的行不算可见行，只变淡、只加 class 的仍算可见行。
